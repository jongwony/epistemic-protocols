# Co-Change Patterns

Protocol modifications require synchronized edits across multiple files. Any protocol change requires `plugin.json` version bump + `/verify`.

This table names co-change targets and the conditions that trigger them; enforcement coverage and commands are inventoried in [verification.md](verification.md).

| Change | Files to update |
|--------|----------------|
| New/modified phase | SKILL.md (formal block + prose) |
| New tool usage | SKILL.md (PHASE TRANSITIONS `[Tool]` + TOOL GROUNDING entry) |
| New loop option | SKILL.md (LOOP + terminal phase prose + Rules) |
| Delegation change | SKILL.md (isolation section), CLAUDE.md (delegation constraint) |
| Any protocol change | `plugin.json` version bump, then `/verify` |
| Dependent protocol interface wording in utility skills | Utility plugin `plugin.json` minor bump when catalog/onboard/reporting text now assumes a changed runtime interface in another protocol |
| New plugin added | `marketplace.json` (plugins array), plugin directory with `plugin.json`, `.agents/plugins/marketplace.json` (Codex marketplace — consumed by `scripts/install-codex.sh`), `<plugin>/.codex-plugin/plugin.json` (Codex manifest mirror), `scripts/package.js` `CODEX_SUBMIT_PLUGINS` (explicit submission set + its length guard — decide inclusion or record the staging) |
| New skill added to existing plugin | `SKILL.md`; `<plugin>/.claude-plugin/plugin.json` (version bump; description only when the plugin's routing cue changes); `<plugin>/.codex-plugin/plugin.json` (matching version in the same commit; `description`, `interface.shortDescription`, `interface.longDescription` only when the Codex routing cue changes); `marketplace.json` description only when the marketplace routing cue changes; `<plugin>/README.md` **and** `README_ko.md` skill table when the skill belongs on the plugin's public skill list — hand-maintained, no static guard, and the two language mirrors move together; the root `README.md` **and** `README_ko.md` utility inventories when the skill belongs on the repo's public utility list — same hand-maintained, no-static-guard, two-mirrors-together shape as the plugin tables, and neither table declares itself a subset, so an omission reads as the skill not existing; `scripts/package.test.js` (expected release-ZIP list); `package.js` (`FIRST_RELEASE_HIGHLIGHTS` Utility Skills selection only when the new skill should appear in the curated fallback used when scoped changelog groups are unavailable; `DESCRIPTION_OVERRIDES` only when the packaged frontmatter description exceeds 200 characters — an override replaces that description rather than escaping the limit, so it answers to the same one, and `package.test.js` asserts the packaged description against it; `PLUGINS` is derived from `discoverPlugins()`, no manual edit) |
| New protocol added | All of the above, plus: `.claude/skills/verify/graph.json` (add the protocol node + its edges — protocol classification is graph-derived, so this gates recognition as a protocol), `scripts/load-protocols.js` (`CANONICAL_PRECEDENCE`, `CANONICAL_CLUSTERS` — hardcoded canonical lists; `PROTOCOL_FILES`/`CANONICAL_PROTOCOLS` are derived from filesystem/SKILL.md, no manual edit), ALL existing SKILL.md (precedence descriptions + distinction tables), onboard (`SKILL.md` Data Sources + `references/scenarios.md` + `references/workflow.md`), catalog SKILL.md, probe SKILL.md (`DeficitName` + `ProtocolId` type sets — the runtime-normative enumeration `/probe` scans against), README.md + README_ko.md, `epistemic-cooperative/agents/coverage-scanner.md` (protocol-usage regex + name→plugin mapping), `.claude/skills/verify/references/review-checklists.md` (Epistemological Soundness — the per-protocol type-signature list). Decorative protocol-count phrases are NOT in this set — they stay count-free per CLAUDE.md §Settled Directions, and canonical-registry-derived test expectations update automatically |
| Precedence change | ALL SKILL.md precedence descriptions, README.md + README_ko.md (concern-cluster workflow), `graph.json` |
| A protocol's TYPES type gains, loses, or renames a constructor | Every `graph.json` edge whose `satisfies` enumerates that type's constructors and how each is handled across the seam — reconcile the enumeration and any per-constructor routing/fallback clause to the new constructor set. Deliberately hand-checked, not statically guarded: `graph.json` carries supplementary connection consistency, not a primary contract surface, so a check here must not become blocking on other work; `satisfies` stays free prose that `static-checks.js` never reads |
| Initiator taxonomy change | ALL SKILL.md (distinction tables + Rule #1), READMEs, `review-checklists.md` |
| Protocol nudge pattern change | Output Style nudge section, plugin.json version bumps |
| Convergence-awareness nudge wording | epistemic-ink.md (Protocol Nudge), `.claude/principles/architectural-principles.md` (Dual Advisory Layer) + `premise/gate-design.md` (Full Taxonomy Confirmation, source of truth) |
| Gate interaction pattern change | ALL SKILL.md Rules + PHASE TRANSITIONS + TOOL GROUNDING + phase prose + plugin.json version bumps |
| Relay interaction pattern change | SKILL.md TOOL GROUNDING + `premise/gate-design.md` (Convergence Evidence, source of truth) + criteria.md + static-checks.js + plugin.json version bumps |
| Derived principle addition | the premise document that owns the principle's family (`premise/gate-design.md`, `premise/instruction-authoring.md`, or `premise/recognition-and-authority.md` — source of truth, with the derivation annotated there) + SKILL.md Rules inline summary in protocols scoped-in per the principle's Scope block (self-contained inline wording; no external reference to rule or premise files) + plugin.json version bumps for affected plugins |
| Architectural principle addition | the general principle → `premise/tiering-and-scope.md` (new tier-tagged section; source of truth) **only when it holds without presupposing a protocol layer — one stated in terms of protocols, their composition, or their coexistence with host tooling goes to `.claude/principles/architectural-principles.md` outright** + this project's instance, if any → `.claude/principles/architectural-principles.md` + cascading reflection in cited rule/principle files (e.g., `.claude/principles/project-profile-calibration.md`, `.claude/rules/project-profile.md`) + SKILL.md inscription **only when gate annotations are directly affected** (e.g., new TOOL GROUNDING entry, new Rule, new Phase prose section — substrate boundary touch is one such case). Profile-layer reclassification alone (rule/principle-file changes without gate annotation changes) does NOT trigger SKILL.md updates — those follow per-protocol future stages pending accumulated use evidence. Plugin.json version bumps only for plugins whose SKILL.md actually changes. If premise layer purification is involved (subsumed paragraph removal), perform removal in the same commit to preserve principle homogeneity |
| Gate axis purification (single TOOL GROUNDING axis) | ALL SKILL.md TOOL GROUNDING (split `(extension)` entries for conditional specialization) + removal of any obsolete dual-axis annotation section + `premise/interaction-factorization.md` (§Interaction Kind Factorization, source of truth) + `.claude/principles/architectural-principles.md` §Authority Mode (configurable relay/constitution boundary) + `premise/gate-design.md` (§Loop Continuity / §Full Taxonomy Confirmation, source of truth) + `.claude/principles/project-profile-calibration.md` + `premise/calibration-methodology.md` + `.claude/rules/project-profile.md` deferral note + verify scripts (`single-axis-soundness` check; removal of any structural check enforcing the obsolete annotation section) + utility skill references (comment-review / steer) + READMEs / agents / styles citing the old regret-axis vocabulary + plugin.json version bumps for affected plugins |
| SKILL.md frontmatter description change (type signature 포함) | `scripts/package.js` DESCRIPTION_OVERRIDES (morphism notation 동기화) |
| Hypomnesis store write pipeline change (mjs harness) | `anamnesis/hooks/hooks.json` (SessionEnd hook registration), `anamnesis/scripts/hypomnesis-write.mjs` (mjs harness implementation), `anamnesis/skills/recollect/SKILL.md` Scan section (read-side pattern), `anamnesis/.claude-plugin/plugin.json` version bump |
| Axiom change (any foundational principle in `premise/recognition-and-authority.md`, `premise/interaction-factorization.md`, or `premise/gate-design.md` / Gate Integrity definition or summary) | `premise/recognition-and-authority.md`, `premise/interaction-factorization.md`, `premise/gate-design.md` (source of truth, split by axiom — no in-repo restatement to keep in sync) + any `.claude/principles/*` section whose project-local binding cites the changed kernel |
| Instruction-authoring principle change (Zero-Shot Instruction Preference / White Bear Avoidance / Subtraction at Revision Time and its nested Actionable revision criterion / Currency is not Support-Integrity / Audience Reach / Direction over Accumulated Workload / Conflicting Instructions) | `premise/instruction-authoring.md` (source of truth) + any section in `.claude/principles/architectural-principles.md` or `.claude/principles/safeguards.md` carrying this project's own grounding instance of the changed principle (the instance does not travel; the principle is not restated) + `premise/gate-design.md` §Guard consistency when the change touches the conflict-repair boundary the two share |
| Mission/vision wording change | `CLAUDE.md` (maintainer umbrella), `docs/mission-bridge.md` (audience boundary + derivation rule), `README.md` + `README_ko.md` (public framing); verify runtime users still rely on `SKILL.md` + plugin descriptions rather than mission docs |
| Editing/Git convention change | `.claude/rules/editing-conventions.md` (primary) → `CLAUDE.md` (reference) |
| Compiled-copy rule wording change (Gate Integrity canonical text in `premise/gate-design.md`, or Formal blocks in `docs/structural-specs.md`) | every protocol SKILL.md compiled Rules entry + `static-checks.js` checks 25–26 LABEL/KERNEL constants + `docs/verification.md` entries 25–26 |
