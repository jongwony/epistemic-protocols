# Chain reference — post-classification law for named material

Read when the request names material — a prior protocol's output in the session, or a record
outside it read by a tool — once that material has folded in, before the first pass. This
reference does not bind on `Entry = Seeded` generally — only when the entry carries named
material.

Each seed keeps the origin tag the material already carries, or otherwise the origin of the
turn it was read from — `external` for a record a tool read — so an assistant's output never
becomes the user's by being chained. Only the record the user named is read; nothing beside it
is scanned. When and under which frame each item lands is `candidates` in SKILL.md.

Chaining material in is the user's deliberate choice of substrate-first over
independent-ideation-first: that choice is their adoption of the material, recorded apart
from its origin rather than written into it.
