# Seeded entry — expand-first, no gate

Read when `Entry = Seeded(seeds)` — before the first pass runs. This is the expand-first
law: why no gate precedes generation, and how the original seeds enter the map.

**Seeded path — no gate.** Frames derived from the seeds go straight to a first pass
(expand-first): the user already committed concrete material, so the early-example
fixation risk the Blank-path gate exists to avoid does not apply the same way here.

How many derived frames the first pass opens is your judgment — enough to show the field
widening, few enough that the round can be taken in. Every frame left closed shows on the
map as unexplored, and a continue that names nothing opens all of them.

On the first pass the original seeds are promoted to candidates under the frame each lands
in — each keeping the origin its seed carried (the user's own fragments as `person`) —
alongside whatever the frames generate as `assistant`; every later pass tags its output
`assistant`.
