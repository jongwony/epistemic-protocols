# Heuresis — /ideate (εὕρεσις)

프레임-병렬 발산 생성으로 저확장 후보장을 넓힘 (εὕρεσις: 발견, 찾아냄, 고안)

> [English](./README.md)

## 이름

그리스어 εὕρεσις는 발견, 찾아냄, 또는 넓은 의미의 고안·착상을 가리킵니다. 후대에 수사학 용어 *inventio*로 특수화된 것은 여러 역사적 협소화 중 하나일 뿐, 여기서 쓰이는 일차적·지배적 의미는 아닙니다.

## Heuresis란?

**아직 선택이 일어나기 전, 후보장 자체가 얇은 순간**을 위한 프로토콜입니다 — 비어 있거나, 근본 목표가 아직 열려 있는데도 하나로 조기 수렴한 상태. 호출 발화만으로 백지인지 이미 조각을 갖고 있는지 추론하고(진입 질문 없음), 백지라면 구체적 아이디어를 보여주기 전에 추상 프레임을 먼저 펼쳐 사용자가 고르게 하며, 사용자가 연 프레임들 위에서 병렬로 후보를 생성합니다 — 그중 무엇도 탈락시키거나 순위 매기거나 고르지 않습니다. 멈추는 시점은 전적으로 사용자 몫입니다.

### 핵심 문제

어떤 후보장은 저확장 상태입니다(`CandidateFieldUnderexpanded`): 목표는 충분히 분명한데 객체-수준 대안이 비어 있거나 조기 수렴했습니다. 발산적 사고와 수렴적 사고는 서로 다른 인지 작업이며, 이 둘을 한 호흡에 섞는 것 — 생성과 판단을 동시에 하는 것 — 이 후보장을 얇게 유지하는 원인입니다. 여기에 두 위험이 겹칩니다: 구체 예시를 너무 일찍 보여주면 정작 촉발하려던 그 발상 자체를 고착시키고, AI 보조 생성은 별도의 장치 없이는 산출물들이 서로 수렴하게 만들 수 있습니다.

### 해법

**선택이 아닌 발산(Divergence over Selection)**: 발화만으로 백지/씨앗 진입을 추론한 뒤 갈립니다 — 백지 진입은 구체 아이디어가 존재하기 전에 추상 프레임 지도를 먼저 봅니다(소유감이 유지되고, 초기 발상을 고착시킬 것이 없습니다); 씨앗 진입은 이미 준 것에서 바로 확장합니다(직접 공급한 재료에는 같은 고착 위험이 적용되지 않으므로). 매 라운드는 열린 프레임들 위에서 병렬로 후보를 생성하며, 모든 후보에 출처(사용자, AI, 또는 체인한 재료가 온 곳)를 태깅하고, 아무것도 폐기하거나 순위 매기지 않습니다. 고정 라운드 할당량은 없습니다 — 후보장의 경계를 긋는 것은 사용자 자신의 멈춤이며, 아무것도 생성되기 전에 멈춘 경우는 정직하게 빈 결과로 타입되지, 만들어진 적 없는 후보장으로 포장되지 않습니다.

### 다른 프로토콜과의 차이

| Protocol | Initiator | Type Signature |
|----------|-----------|---------------|
| Euporia | Hybrid | `AbstractAporia → ResolvedEndpoint` |
| Proplasma | Hybrid | `DirectionUnrecognizable → DirectionalContrast` |
| **Heuresis** | **User-initiated** | **`CandidateFieldUnderexpanded → DiverseCandidateField`** |

**위치**: heuresis의 `GenerationFrame`은 고정된 탐구 위에 놓는 분석적 렌즈가 아니라, 병렬 발상 생성을 위한 임시 분할일 뿐 분석적 관점으로 이관되지 않습니다. Proplasma는 후보가 이미 2개 이상 있고 선택 전에 직접 봐야 할 때 미리보기를 제공합니다 — heuresis는 그보다 상류, 후보장 자체를 넓혀야 하는 지점에 있습니다. Euporia는 외재화된 substrate(코드베이스·규칙·과거 세션)에서 결정 좌표를 역추적합니다 — heuresis는 그 substrate를 스캔하지 않으며, 사용자의 말과 사용자가 명시적으로 이름한 재료 — 이전 프로토콜의 산출물, 또는 대신 읽어 오는 이슈 같은 기록 — 만 읽습니다.

**라우팅 우선순위**: 후보가 이미 2개 이상 있고 보기만 하면 될 때 → `/preview`; 씨앗 재료를 아직 찾거나 모아야 할 때 → 수집 프로토콜(예: `/inquire`)을 먼저 돌리고 그 산출을 체인으로 실어옴, 이름을 댈 수 있는 기록(이슈, 문서)은 `/ideate` 가 바로 읽음; 후보장 자체가 얇거나 정체됐을 때 → **`/ideate`**.

## 체인 경계

heuresis는 사용자가 준 것을 읽습니다: 요청, 진행 중에 사용자가 하는 말, 그리고 사용자가 명시적으로 이름한 재료 — 이전 프로토콜의 산출물, 또는 이슈나 문서처럼 세션 밖에 있어 대신 읽어 오는 기록. 이름하지 않은 것 — 세션 전체·코드베이스·규칙 — 은 뒤지지 않습니다. 이런 식으로 재료를 체인해오면 그것은 사용자의 의도적인 substrate-우선 선택입니다 — 발화를 쓰기 전에 이미 재료를 읽었으므로, 사전 재료를 보기 *전에* 발상하는 독립-발상의 소유감·다양성 이점은 그 경로에서 성립하지 않습니다. heuresis는 이를 있는 그대로 명시하며, 별도의 우회 장치를 두지 않습니다.

## 사용법

```
/ideate [주제, 또는 이미 가진 몇 가지 조각]
```

heuresis는 호출을 읽고 백지/씨앗 진입을 추론합니다 — 백지라면 아무것도 생성하기 전에 사용자가 고를 추상 프레임 지도를 먼저 엽니다. 이후 매 라운드는 열린 프레임들 위에서 병렬로 후보를 생성하고, 출처를 태깅하며, 아직 열지 않은 프레임을 함께 제시합니다. 프레임을 더 열거나, 직접 새 각도를 이름 붙이거나, 한 프레임이나 후보 하나 아래를 더 파자고 해서 계속할 수 있습니다 — 파기는 그 아래에 가지를 치고, 매 라운드는 후보장 전체를 한 장의 지도로 다시 그리며 그 라운드에 새로 붙은 것을 표시합니다. 후보장이 충분히 넓고 깊어졌다면 언제든 멈출 수 있고, 멈춘 자리는 다음 `/ideate` 가 이어 갈 수 있는 체크포인트가 됩니다. 이렇게 만들어진 후보장 — 주제, 출처 태깅된 후보들, 프레임과 가지, 아직 탐색하지 않은 것, 나중으로 미뤄 둔 것 — 은 `/preview`, 직접 판단, 이슈 트래커, 혹은 다음에 올 어떤 평가 작업으로든 흘러갈 수 있는 엔드포인트-중립 계약입니다.
