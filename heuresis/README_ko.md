# /ideate — Heuresis (εὕρεσις)

> [English](./README.md)

<a name="heuresis--ideate-εὕρεσις"></a>
<a name="핵심-문제"></a>
## 언제 쓰나요

목표는 분명한데 떠올린 대안이 없거나, 선택지가 너무 일찍 하나로 좁혀졌을 때가 있습니다. 아이디어를 내는 일과 평가하는 일을 동시에 하면 후보군이 쉽게 좁아지고, 구체적인 예시를 너무 일찍 보면 생각이 거기에 묶이기 쉽습니다. 하나를 고르기 전에 선택지를 넓게 펼치거나 예전에 탐색하던 아이디어 지도로 돌아가고 싶을 때 `/ideate`를 씁니다.

<a name="사용법"></a>
<a name="해법"></a>
## 시작하기

```
/ideate [주제, 또는 이미 가진 몇 가지 조각]
```

`/ideate`를 입력하면 AI는 별도의 진입 질문 없이 요청 내용(그냥 `/ideate`만 쳤다면 앞선 대화)을 보고 백지에서 시작하는지, 이미 몇 가지 조각을 가지고 시작하는지, 아니면 이전 아이디어 지도를 이어 가자고 하는지 파악합니다. 백지에서 시작할 때는(요청에서 이미 관점을 지정하지 않았다면) 구체적인 예시가 생각을 묶지 않도록 추상적인 관점(프레임) 지도를 먼저 펼쳐 고르게 합니다. 그다음 라운드마다 열린 관점들에서 병렬로 후보를 만들어 내며, 어떤 후보도 임의로 빼거나 순위를 매기지 않습니다. 매 라운드가 전체 지도를 다시 그려 보여 주므로, 새로 나온 아이디어를 앞서 뻗은 가지들과 나란히 볼 수 있습니다. 새로운 관점을 더 열거나, 직접 아이디어를 보태거나, 특정 관점이나 후보 하나를 더 깊이 파서 아래로 가지를 치며 탐색을 이어 갈 수 있습니다.

## 끝나면 무엇이 남나요

탐색한 아이디어 전체가 한 장의 지도로 남습니다. 각 관점과 그 아래로 판 가지들, 후보마다 표시된 출처(내가 낸 것, AI가 낸 것, 지정해 가져온 자료), 아직 열어 보지 않은 영역, 범위 밖으로 빼거나 보류해 둔 항목까지 한눈에 볼 수 있습니다. 무엇도 미리 선택되거나 순위가 매겨지지 않은 상태이므로, 원하는 시점에 이 지도를 그대로 받아 `/preview`로 넘기거나 직접 고르거나 이슈 트래커 등 다음 평가 단계로 가져가면 됩니다.

<a name="이름"></a>
<a name="heuresis란"></a>
**이름**: 그리스어 εὕρεσις는 발견, 찾아냄, 또는 넓은 의미의 고안·착상을 가리킵니다. 후대에 수사학 용어 *inventio*로 특수화된 것은 여러 역사적 협소화 중 하나일 뿐 여기서 쓰이는 중심 의미는 아닙니다.

**선택이 아닌 발산(Divergence over Selection)**: 백지 진입은(요청이 이미 틀을 이름하지 않는 한) 구체 아이디어가 나오기 전에 추상 프레임 지도를 먼저 보고, 조각을 가지고 시작하는 씨앗 진입은 사용자가 준 재료에서 바로 확장합니다. 각 라운드는 AI가 판단을 밝히고 새로운 프레임을 열어 넓힘을 이어 갈 수 있지만, 사용자가 범위 밖으로 둔 영역으로는 넓히지 않으며 무엇을 왜 열었는지 밝힙니다. 정해진 라운드 수는 없으며 사용자가 지도를 받아 갈 때 경계가 정해집니다(후보가 하나도 없을 때는 아직 받아 갈 수 없습니다). 그만하겠다고 하거나 다른 일로 넘어가면 탐색은 그 자리에 머물고, 나중에 이어 가자고 요청하거나 앞선 대화 맥락상 맨 `/ideate`가 이어 가는 뜻으로 읽히면 앞서 받아 갔든 아니든 그 지도를 재개하며, 새 주제를 주면 새 지도를 엽니다.

<a name="체인-경계"></a>
### 체인 경계

heuresis는 사용자가 준 것만 읽습니다: 요청, 진행 중에 하는 말, 그리고 명시적으로 이름을 댄 자료(이전 프로토콜의 산출물, 또는 대신 읽어 오는 이슈·문서 같은 세션 밖 기록). 이름을 대지 않은 세션 전체나 코드베이스, 규칙은 후보장에 들어오지 않으며, 지금까지의 대화는 사용자가 무엇을 뜻하는지(맨 `/ideate` 포함) 읽을 때만 참고합니다. 외부 자료를 이처럼 체인으로 연결해 오면 호출 전에 이미 자료를 본 셈이므로, 사전 자료를 보기 *전에* 발상할 때 얻는 소유감과 다양성 이점은 그 경로에서 적용되지 않습니다. heuresis는 이를 있는 그대로 밝히며 별도의 우회 장치를 두지 않습니다.

<summary>다른 프로토콜과의 비교</summary>

<a name="다른-프로토콜과의-차이"></a>
| Protocol | Initiator | Type Signature |
|----------|-----------|---------------|
| Euporia | Hybrid | `AbstractAporia → ResolvedEndpoint` |
| Proplasma | Hybrid | `DirectionUnrecognizable → DirectionalContrast` |
| **Heuresis** | **User-initiated** | **`CandidateFieldUnderexpanded → DiverseCandidateField`** |

- **위치**: heuresis의 `Frame`은 병렬 발상 생성을 위한 임시 분할일 뿐 분석적 관점으로 이관되지 않습니다. Proplasma(`/preview`)는 후보가 이미 2개 이상 있을 때 선택 전에 모습을 미리 보여 주고, heuresis는 그보다 앞서 후보군 자체를 넓혀야 하는 지점에 있습니다. Euporia(`/elicit`)는 의도가 걸린 결정 좌표를 사용자의 말과 자료(코드베이스·규칙·과거 세션)에서 찾지만, heuresis는 사용자가 명시적으로 지정한 기록만 읽고 코드베이스나 규칙을 임의로 스캔하지 않습니다.
- **라우팅 우선순위**: 후보가 이미 2개 이상 있고 모습만 확인하면 될 때 → `/preview`; 바탕이 될 자료를 아직 찾아 모아야 할 때 → 수집 프로토콜(예: `/inquire`)을 먼저 돌리고 그 결과를 연결(이름을 댈 수 있는 이슈나 문서는 `/ideate`가 바로 읽음); 후보군 자체가 얇거나 막혀 있을 때 → **`/ideate`**.
