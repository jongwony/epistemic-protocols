# Route — /route

쌓인 세션 컨텍스트가 드러내는 결핍에 맞는 코어 epistemic 프로토콜로 라우팅하고, 그 프로토콜을 호출합니다.

> [English](./README.md)

## Route란?

각 epistemic 프로토콜 자신의 description은 그 프로토콜이 해소하는 상호작용 결핍을 명명합니다. 그것과 실제 호출 사이에 두 가지가 놓여 있고, 그중 하나만이 계기입니다. 다른 하나는 목록입니다 — 호스트의 loaded-skills 리스팅은 각 스킬의 description을 함께 실을 수도 있고, 커맨드 식별자만 실을 수도 있습니다. 식별자만 실릴 때 루프 위의 에이전트는 어떤 프로토콜이 무슨 결핍을 해소하는지에 대한 진술을 하나도 들고 있지 않습니다. 그러면 *컨텍스트가 로드된 어떤 프로토콜이 해소하는 결핍을 보여주는가* 라는 형태의 판별은 프롬프트 시점에 컨텍스트에 없는 목록에 대조하라는 요구가 되고, 결코 발동하지 않습니다.

이 공백은 드문 예외가 아니고, 하필 Route가 필요한 자리에서 가장 심합니다. 호스트가 리스팅을 크기 예산 아래 배급할 때 남기는 description은 최근 사용으로 정당화되는 것들이고, 떨어져 나가는 것은 사용자가 부르지 않아 온 스킬의 것 — 바로 Route가 닿으려는 집합입니다. 배급은 그렇게 Route의 목적과 반대 방향으로 작동하고, 조용히 그리고 부분적으로 그렇게 하므로, 채워져 보이는 리스팅이 정작 들어맞는 프로토콜 자리에서만 비어 있을 수 있습니다.

Route가 둘 다를 나눠 공급합니다: **언제는 훅들이 정하고, 무엇은 스킬이 정합니다.** `SessionStart` 훅이 판별에 필요한 목록을 컨텍스트 머리에, 컨텍스트 에포크마다 한 번 놓습니다 — 설치된 프로토콜마다 한 줄, 커맨드와 그것이 해소하는 결핍의 이름 — 그 에포크가 어떻게 시작됐는지를 말하는 여는 문장 아래에. `UserPromptSubmit` 훅은 매 프롬프트 옆에 짧은 지시문을 놓습니다. 호스트의 리스팅이 무엇을 실어 왔든 상관없이 판별이 프롬프트 시점에 평가 가능해집니다. `/route` 스킬은 호출되고 나면 로드된 프로토콜 식별자를 후보 집합으로 삼고, 각 후보의 결핍을 그 프로토콜 자신의 description에서 해소합니다 — 리스팅이 이미 그것을 실어 왔다면 아무것도 더 읽지 않습니다 — 그리고 정확히 하나의 프로토콜 결핍이 컨텍스트가 보여주는 것일 때 그 프로토콜을 호출합니다. description을 해소할 수 없는 후보는 이름이 무엇을 뜻할지 추측해 매칭되는 대신 후보에서 빠집니다. 호출된 프로토콜 자신의 Phase 0 감지와 첫 게이트가 사용자 판단의 자리로 남고, Route는 자기 게이트를 추가하지 않습니다.

테이블이 하는 일은 발동이지 매칭이 아닙니다. 턴이 어떤 결핍으로 흘러들었다는 것을 알아채는 데는 결핍 이름만으로 충분하고, 그 이름이 줄여 쓴 전체 서술은 실제로 매칭이 일어나는 `/route` 안에서 해소됩니다. 이 분업이 테이블을 프로토콜당 한 줄로 붙잡아 두고, 그것을 세션 시작에 놓는 것이 매 프롬프트 비용을 지시문 하나로 붙잡아 둡니다.

| 결과 | 조건 |
|------|------|
| 프로토콜 호출 | 로드된 프로토콜 하나가 지배적으로 맞을 때 |
| 프로토콜별 넛지 한 줄 (`↗ /command — reason`) | 여럿이 맞거나, 하나뿐인 매치가 약할 때 |
| 침묵 | 아무것도 맞지 않을 때 — 가장 흔한 경우 |

## 훅이 주입하는 것

`hooks/hooks.json`은 command 훅 두 개를 등록합니다. 둘 다 `hookSpecificOutput.additionalContext`를 쓰고, stdin의 payload를 읽되 필수로 요구하지 않으며, 모든 경로에서 0으로 종료합니다. 파일을 쓰지 않고, 네트워크를 건드리지 않으며, 세션 내용이 프로세스 밖으로 나가지 않습니다.

**`SessionStart` → `scripts/route-session.mjs`** 는 결핍 테이블을 컨텍스트 에포크마다 한 번 실어 나릅니다. 호스트는 에포크가 왜 시작됐는지를 payload의 `source` — `startup`, `resume`, `clear`, `compact` — 로 알려주고, 컴팩션 뒤에 이 훅을 다시 발화시키므로, 컴팩션이 테이블을 걷어낸 바로 그 시점에 테이블이 다시 컨텍스트에 들어옵니다 — 트랜스크립트를 읽지 않고, 마커도 두지 않고. 여기서 주입된 테이블은 컨텍스트 머리, 캐시된 프리픽스 안에 놓입니다. 테이블 앞에 두 줄짜리 여는 문장이 오고, 그 내용은 source에 따라 갈립니다: 시작이나 `/clear` 뒤에는 컨텍스트가 얇고, 완전히 명시적이지 않은 요청은 과제보다 결핍을 먼저 드러내는 것이 보통이다; resume이나 컴팩션 뒤에는 세션이 이미 정리한 것이 시야 밖에 있을 수 있고, 회상 형태의 결핍이 가장 먼저 확인할 것이다. 여는 문장은 조건을 말할 뿐 프로토콜 이름을 대지 않습니다 — 그것은 스킬의 Rule #2가 거부하는, 손으로 유지하는 라우팅 표가 됩니다; 모델이 그 조건을 바로 아래의 테이블에 대조합니다.

테이블은 유도되며, 유지되지 않습니다. `installed_plugins.json`이 활성화된 각 플러그인의 설치 경로를 주고, 스킬이 정확히 하나이며 그 `SKILL.md`의 MORPHISM 블록이 `deficit:`을 선언할 때 그 플러그인을 코어 프로토콜로 봅니다 — Route 자신은 제외되는데, 자기 자신으로는 라우팅하지 않기 때문입니다. 그래서 설치되지 않은 프로토콜은 나타날 수 없고, 스위트에 프로토콜이 추가돼도 여기를 고칠 일이 없으며, 손으로 동기화하는 목록이 없습니다. 선별 기준은 frontmatter의 `Type: (...)` 절이 아니라 `deficit:` 줄입니다. 그 절은 스위트 전체에서 균일하지 않아, 그것을 기준으로 잡으면 프로토콜 하나가 말없이 빠집니다. 모든 실패 경로는 열려 있습니다: 읽을 수 없는 payload는 `startup`으로 읽히고, 설정을 읽을 수 없거나, 설치 레이아웃을 알아볼 수 없거나, 해소된 프로토콜이 하나도 없으면 여는 문장만 나갑니다.

**`UserPromptSubmit` → `scripts/route-prompt.mjs`** 는 `/route`의 발동 조건을 매 프롬프트 옆에 실어 나릅니다 — 네 줄짜리 지시문, 그리고 그것뿐입니다. 매 프롬프트 비용은 지시문 하나이고, 테이블은 에포크당 한 번 지불됩니다.

Codex는 같은 `hooks/hooks.json`을 읽습니다. 지원이 확인된 것은 `UserPromptSubmit` 이벤트와 같은 `additionalContext` 출력 필드까지이고, `SessionStart`는 확인되지 않았습니다. `SessionStart` 훅을 돌리지 않는 호스트에서는 테이블이 도착하지 않고, Route는 지시문과 스킬 자신의 후보별 결핍 해소로 동작합니다. Codex는 플러그인 동봉 훅을 현재 정의가 신뢰될 때까지 건너뜁니다 (설치 참조).

## 설치

Claude Code:

```
claude plugin marketplace add https://github.com/jongwony/epistemic-protocols
claude plugin install route@epistemic-protocols
```

Codex:

```
codex plugin marketplace add https://github.com/jongwony/epistemic-protocols.git
codex plugin add route@epistemic-protocols
```

그 다음 플러그인의 훅을 검토하고 신뢰하세요 — 플러그인 설치가 훅을 신뢰하는 것은 아니며, Codex는 플러그인 동봉 훅을 현재 정의가 신뢰될 때까지 건너뛰므로, 이 단계 전까지 매 프롬프트 지시문은 꺼져 있습니다:

```
/hooks
```

Codex는 훅 정의의 해시에 대해 신뢰를 기록하므로, 플러그인의 훅이 바뀔 때마다 이 단계가 반복됩니다.

## 사용법

훅들이 일을 하므로 입력할 것은 없습니다. 현재 컨텍스트에 대해 같은 패스를 수동으로 돌리려면:

```
/route
```
