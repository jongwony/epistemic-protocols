# /ground — Analogia (ἀναλογία)

> [English](./README.md)

<a name="analogia--ground-ἀναλογία"></a>
<a name="핵심-문제"></a>
<a name="사용-시점"></a>
## 언제 쓰나요

익숙한 패턴이나 이전 설계, 다른 작업의 구조를 지금 코드베이스에 옮겨 오거나 일반적인 주장을 실제 사례에 대어 볼 때가 있습니다. 예를 들어 Strangler Fig 마이그레이션 패턴이 그럴듯해 보여도, 서비스들이 단일 DB를 공유하는 모놀리스에 그대로 들어맞을지는 별개의 문제입니다. 비유나 이전 설계에 기대어 작업을 시작하기 전에 어떤 결론이 실제로 뒷받침되고, 어디서 막히며, 무엇을 더 확인해야 하는지 먼저 짚어 보고 싶을 때 `/ground`를 씁니다.

<a name="사용법"></a>
<a name="해결책"></a>
## 시작하기

```
/ground [감사할 매핑과 의도된 결론]
```

`/ground`를 입력하면 AI는 먼저 비교의 목적, 확인하려는 결론, 비교할 원본과 대상을 여러분의 말에서 읽습니다. 아직 열려 있는 부분이 있으면 맥락에서 질문 초안을 잡으며, 질문이 여러 가지로 해석되면 AI는 각각 어떤 근거에서 나왔고 무엇을 확인하게 되는지 보여 줍니다. 질문을 고치거나 바꿀 수 있고, AI가 초안으로 먼저 검토했다면 그 사실을 밝힙니다. 이어서 닿을 수 있는 자료를 직접 찾아 두 대상이 어떻게 대응하는지 사슬 전체로 맞추어 보고, 단순히 여러분의 동의를 구하는 대신 실제 증거가 각 주장을 뒷받침하는지 점검합니다.

## 끝나면 무엇이 남나요

자료를 모은 결과 검토할 결론이 하나도 남지 않는 경우(이때는 판정 없이 질문 초안만 제시됩니다)를 제외하면, 확인하려던 결론마다 감사 보고서가 남습니다. 각 결론을 지탱하는 관계가 무엇인지, AI가 어디를 확인해 무엇을 찾았고 어디에는 닿지 못했는지, 모은 자료 중 무엇이 서로 충돌하는지, 대상 쪽에 어떤 차이가 있으면 결론이 깨지는지 한눈에 볼 수 있습니다. 결론마다 한계와 함께 성립하는지, 막혔는지, 아니면 무엇이 빠져 누구의 확인이 더 필요한 미결 상태인지 구분해 돌려받습니다.

<a name="analogia란"></a>
**이름**: 그리스어 ἀναλογία(유비, 유추) — 추상 프레임워크가 눈앞의 사례에 대해 무엇을 어디까지 결론 내리게 허가하는지 감사하는 프로토콜입니다.

**보증은 인용된 증거를 따르며 동의를 따르지 않습니다**: 여러분의 동의는 코드베이스에 관한 증거가 아닙니다. 평가를 움직이는 것은 사실, 출처, 반례, 또는 무언가를 실행해 얻은 결과입니다.

<a name="프로토콜-흐름"></a>
### 프로토콜 흐름

```
질문      → 당신의 말에서 읽는다: 목적, 걸린 결론, 아직 열려 있다면 원천과 대상.
            말이 그것을 열어 두면 맥락에서 초안을 잡은 질문을 보여 받거나 고치거나 바꾸게
            하고, 감사는 그 초안 위에서 이어 갈 수 있으며 그렇다고 밝힌다.
모으기    → 매핑이 기대는 곳을 닿는 데까지. 들여다본 곳은 닿았든 못 닿았든 이름으로 남긴다
평가      → 대응을 구성하고, 걸리는 주장마다 무엇이 무너뜨릴지 적고, 여기서 닿는 검사를
            수행하고, 근거에서 보증을 읽고, 결론마다 판정한다
제시      → 평가 전체를 제시하고 진행한다 (relay — 판정을 요구하지 않는다).
            그다음 당신이 요청하는 일은 계약의 `seam` 을 따른다
이후      → 감사에 닿는 발화는 통째로 읽어 그 위에서 다시 감사하고, 그 밖의 발화 — 결론의
            채택 · 제쳐 둠, 현재 근거만으로 다 답할 수 있는 질문 — 에는 답만 한다
```

이식이나 마이그레이션처럼 구조를 옮기는 목적이라면 더 좁게 묻지 않는 한 구조 전체가 보존되는지 확인합니다. 감사할 결론이 있는 회차는 모으기가 감사할 결론을 남기지 않는 한 평가로 끝납니다. 원천을 어떻게 읽는지에 따라 결론의 판정이 갈리고 증거가 이를 정하지 못하면 각 읽기의 판정을 나란히 보여 준 채 미결로 두며, 뜻하는 읽기를 지정하면 다시 감사합니다. 다른 작업으로 넘어가도 열린 질문은 닫히지 않고 남습니다. 다음 요청은 계약의 [`seam`](./skills/ground/SKILL.md)을 따릅니다.

<a name="이후-발화가-하는-일"></a>
### 이후 발화가 하는 일

| 발화 | 효과 |
|------|------|
| **근거 인용** | 관련성과 범위를 확인하고, 그 근거를 넣어 다시 감사한 뒤 결론을 판정한다 |
| **결론 채택 / 제쳐 둠** | 당신의 것으로 기록되고, 증거와 분리해 보고되며, 보증을 움직이지 않고 새 회차를 열지 않는다. 다음 일을 시키는 것은 채택이 아니다 |
| **초안 질문을 받음 · 고침 · 바꿈** | 당신의 턴이 질문을 정하면 질문이 그 턴 위에 선다. 그 질문을 먼저 제시하고 감사한다. 모은 증거는 이어진다 |
| **목적 · 결론 · 원천 · 대상 변경** | 바뀐 질문을 먼저 제시하고 다시 감사한다. 모은 증거는 이어지고, 판정은 다시 내린다 |
| **뜻하는 읽기를 말함** | 질문의 결론이 무슨 뜻인지 정하고, 판정은 그 읽기 아래에서 다시 내려진다 |
| **이 감사에 대한 질문** | 현재 근거만으로 다 답할 수 있으면 답한다. 그 밖의 질문 — 근거가 정하지 못하는 것, 사실 · 출처 · 반례 · 결과를 가져온 것 — 은 새 회차를 연다 |
| **무관한 발화** | 답만 한다. 마지막 결과가 그대로 선다 |

### 건너뛰어도 되는 경우

- 비유나 매핑이 무엇을 뒷받침하는지 맥락에서 이미 정해졌을 때
- 기대고 있는 매핑이 없을 때
- 매핑 없이 두 영역 중 한쪽의 설명만 원할 때 (감사에 설명이 필요하면 Analogia가 직접 증거로 읽습니다)

<summary>다른 프로토콜과의 비교</summary>

<a name="다른-프로토콜과의-차이"></a>
| 프로토콜 | 주도자 | 타입 시그니처 |
|----------|--------|---------------|
| Aitesis | AI-guided | `ContextInsufficient → SufficientContext` |
| **Analogia** | **AI-guided** | **`MappingUncertain → MappingAssessment`** |
| Proplasma | Hybrid | `DirectionUnrecognizable → DirectionalContrast` |
| Merismos | User-initiated | `GoalPlanUncompiled → ConditionBearingUnitPlan` |
| Epharmoge | AI-guided | `ApplicationDecontextualized → ContextualizedExecution` |
| Katalepsis | User-initiated | `TargetUngrasped → VerifiedUnderstanding` |

- **vs. Aitesis**: Aitesis는 AI가 닿을 수 있는 사실을 모으고 사용자만 쥔 것을 구분합니다(사실 관계). Analogia는 구조적 주장에 대한 증거에서 매핑이 무엇을 허가하는지 감사합니다(관계 구조).
- **vs. Epharmoge**: Epharmoge는 실행 후 적용성을 확인합니다. Analogia는 추상화 수준 사이의 매핑이 허가하는 결론을 감사합니다.
- **vs. Proplasma**: Proplasma는 설명만으로 방향의 결과를 알아보기 어려울 때 버릴 시제품(placeholder probe)으로 대비합니다. Analogia는 기대고 있는 매핑을 감사하며, Proplasma에서 정한 방향의 결론이 매핑에 기댈 때 이어서 감사할 수 있습니다.

**판별 기준**: 불확실성이 *구조 A의 매핑이 B에 대해 무엇을 허가하는가*에 관한 것이면 Analogia이고, *AI가 닿을 수 있는 사실과 사용자만 쥔 사실이 무엇인가*에 관한 것이면 Aitesis입니다.
