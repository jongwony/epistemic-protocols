# /conduct — Hyphegesis (ὑφήγησις)

> [English](./README.md)

<a name="hyphegesis--conduct-ὑφήγησις"></a>
<a name="hyphegesis란"></a>
<a name="핵심-문제"></a>
목표는 분명하지만 작업이 여러 갈래로 나뉘어 어떻게 진행할지 정해지지 않았을 때가 있습니다. 어떤 갈래를 순서대로 혹은 나란히 돌릴지, 결과를 합치기 전에 서로의 결과를 보게 할지, 결과를 어떻게 합치고 언제 멈추며 어디로 보낼지 분명하지 않은 상황입니다. 작업 방식을 정하지 않은 채 여러 단계의 일을 시작하면 순서가 꼬이거나, 합치기 전에 관점이 섞이거나, 멈출 기준 없이 표류하기 쉽습니다.

## 시작하는 법

<a name="사용법"></a>
<a name="해결책"></a>
```
/conduct 이 서비스를 프레임워크 v2에서 v3으로 마이그레이션
```

여러 갈래로 나뉘는 작업을 시작할 때(또는 진행 도중에) `/conduct`를 입력합니다. 처음 입력한 말에서 이미 작업 방식이 다 정해져 있지 않다면, AI는 무엇을 묻기 전에 방법 전체를 지도 한 장으로 먼저 펼쳐 보입니다. 작업 갈래들과 각 갈래를 누가 어디서 실행하는지, 어떻게 합치고 언제 멈추며 결과가 어디로 가는지, 실행하는 쪽에 필요한 능력과 각각이 실제 환경에서 관찰되었는지, 근거가 나올 때까지 미룬 결정, 그리고 별도의 지휘가 필요 없다고 보는 반대 근거까지 한 장에 담깁니다. 지도는 목표에 비추어 값어치가 있는 만큼만 정밀하게 그리며, 시도해 보는 비용이 싸고 되돌릴 수 있다면 거친 지도로 한 번 돌려 보고 점검하는 방식을 택하기도 합니다.

언제 멈출지, 결과를 어떻게 합칠지, 결과가 어디로 갈지, 작업에 걸린 제약, 그리고 맡기는 권한과 그 한도는 여러분이 직접 쥡니다. 지도의 어느 부분이든 고치거나 그대로 받아들일 수 있으며, 확정하기 전에 답을 주면 앞단에서 바꾼 내용에 맞춰 뒷부분 초안이 다시 채워지고 여러분이 직접 정한 값은 그대로 유지됩니다. 작업이 도는 동안 자리를 비울 예정이라면, 떠나기 전에 정해야 할 결정과 다녀올 때까지 기다려도 되는 결정을 지도에서 미리 갈라 줍니다. 방식을 확정하기 전에는 언제든 그만둘 수 있으며, 그만두면 그때까지의 상태 그대로 남습니다.

## 실행하고 나면 무엇이 남나요

작업 방식을 확정하면 AI가 그 턴에서 바뀐 내용을 반영해 지도를 한 번 더 보여 주고 — 첫 요청에서 이미 방식이 다 정해져 있었다면 지도를 한 번 보여 준 뒤 — 기다리지 않고 같은 턴에서 바로 그 내용을 실어 다음 실행으로 넘기고 `/conduct`를 마칩니다. `/conduct` 자체는 작업을 직접 실행하는 대신 작업 방식을 설계해 넘기는 역할을 합니다. 이제 여러 갈래가 어떤 순서로 돌고 어떻게 합쳐지며 어디서 멈추고 결과가 어디로 가는지, 또 무엇을 맡기고 무엇을 직접 쥐었는지 분명히 알고 작업 방식을 내 것으로 삼을 수 있습니다.

<details>
<summary>방법이 정하는 것</summary>

<a name="방법이-정하는-것"></a>
### 방법이 정하는 것

무엇을 묻기 전에 먼저 펼치는 지도 한 장에는 다음 항목이 담깁니다: 작업이 무엇을 위한 것인지, 그래프로 그린 작업 갈래들(그래프를 그릴 수 없는 곳에서는 들여쓴 개요), 각 갈래를 누가 어디서 실행하는지(환경이 설명하는 도구를 바탕으로 한 AI의 추론임을 표시), 갈래를 어떻게 합치고 언제 멈추며 결과가 어디로 가는지, 실행하는 쪽에 필요한 능력과 각 능력이 설명이 아니라 환경이 실제로 돌려준 결과에서 관찰되었는지, 근거가 생길 때까지 미룬 결정, 그리고 AI의 반대 근거(이 작업에 지휘가 필요 없다고 읽는 경우 포함).

지도가 눈앞의 작업에서 답하는 물음들입니다. 사용자의 몫으로 표시된 줄은 여러분의 말로만 정해집니다:

| 물음 | 정하는 것 |
|------|-----------|
| 작업의 갈래 | 어떤 생각의 갈래가 필요하고 각각 무엇을 하는가 — 사용자가 다음으로 선언한 프로토콜도 그 결과를 받을 갈래들 뒤에 놓인 한 갈래이며, 사용자의 제약으로 기록됩니다 |
| 순서 | 차례로, 나란히, 또는 의존 관계가 허락하는 대로 실행하는가 |
| 독립성 | 결과가 합쳐지기 전에 갈래들이 서로의 결과를 보는가 |
| 합치기 | 따로 나온 결과를 어떻게 합치는가(사용자의 몫) |
| 멈춤 | 각 갈래와 방법 전체가 언제 멈추는가(사용자의 몫) |
| 결과가 갈 곳 | 방법 너머로 각 결과가 어디로 가는가 — 예컨대 다음 작업 단위(사용자의 몫) |
| 제약 | 작업에 걸린 것 — 누가 실행할지에 대한 방향, 사용자가 자리에 있는지, 기한 등(사용자의 몫) |
| 권한 | 사용자가 맡기는 권한과 그 한도, 큰 방향으로(사용자의 몫) |

근거가 나중에 나오는 결정은 미루어 두되, 이미 기록된 여러분의 권한 범위 안에 있으면 그 권한이 덮는 것으로 지도에 표시하고 그렇지 않으면 여러분에게 다시 묻습니다. 비밀 정보 설정이나 런타임 배포처럼 여러분만 줄 수 있는 것은 언제나 여러분에게 돌아옵니다. 또한 `/compact`, `/clear` 이후나 새 세션으로 건너가야 하는 결과는 방법을 실행하는 쪽이 기록으로 남기고 다음 세션이 그 기록을 가리키도록 합니다. `/conduct` 자체의 추론은 한 세션 안에 머물며, 기록된 결과만 세션을 건너갑니다.

<details>
<summary>다른 프로토콜과의 비교 및 그리스어 이름</summary>

**Hyphegesis**(ὑφήγησις, 바로 앞서 나가 이끌기)는 방법이 미정인 상태(`MethodUnderdetermined`)에서 세션의 인식 작업을 어떻게 수행할지 지휘하여, 사용자가 정한 것과 미룬 결정, 수명, 실행에 필요한 능력을 실어 넘기는 `ConductedMethod`를 만듭니다.

<a name="다른-프로토콜과의-차이"></a>
### 다른 프로토콜과의 차이

| 프로토콜 | 개시자 | 타입 시그니처 |
|----------|--------|---------------|
| Horismos | AI-guided | `BoundaryUndefined → DefinedBoundary` |
| **Hyphegesis** | **Hybrid** | **`MethodUnderdetermined → ConductedMethod`** |
| Katalepsis | User-initiated | `TargetUngrasped → VerifiedUnderstanding` |
