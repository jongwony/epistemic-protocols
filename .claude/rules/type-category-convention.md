# Type Category Convention

TYPES blocks use three distinct type categories, each with its own definitional style:

- **Input types** (morphism domain): Natural language definition with source-agnostic enumeration. The morphism treats inputs uniformly — protocol behavior does not branch on subtypes. Subtypes enumerate conceptual scope for readers, not dispatching targets. Coproduct structure is inappropriate because it implies behavioral branching that does not exist in PHASE TRANSITIONS.
- **Classification types** (processing taxonomy): Open set ∪ Emergent(T). Used for categorization during detection/assessment. Open because new categories can emerge from context.
- **Answer types** (gate response): Closed coproduct. Each constructor leads to a distinct processing path in the subsequent phase. Closed because the protocol must handle all cases.

**The dispatch-structure test.** If PHASE TRANSITIONS handle each case differently, use coproduct. If the protocol processes uniformly regardless of input category, use natural language definition.

**The volatility criterion.** The dispatch-structure test settles which *form* a TYPES entry takes; this one settles whether the type layer carries the category at all. TYPES is a protocol contract's rigid layer, and a rigid layer codifies only deterministic logic — a fragile or heuristic step belongs to the instruction layer instead. The judgment this criterion governs sits at the meta level — whether the type should admit a category at all — and not at the level of a single run. Sorting a particular item into an already-admitted category *inhabits* the type and was never a TYPES question: a form with three fields is stable however differently each run fills them. A category earns its place when the need for it is general, and admitting one narrows the category space rather than editing it per run; `Emergent(T)` is the declared mechanism for admitting a category the authored set did not anticipate, and that admission is itself a meta-level act. What stays out of TYPES is a category that only ever names one run's circumstance — that is the fast-layer judgment, and it belongs to the instruction layer.

**The openness criterion.** The volatility criterion settles whether an entry belongs in TYPES; this one settles how much of an admitted entry may be fixed before the run it governs. Ask what independently determines the boundary of its value space, held apart from what later selects or fills one value inside it. They are separate questions: that a person selects the value at runtime neither grounds nor ungrounds the boundary, and collapsing the two condemns every sound closed answer type at once. An authored boundary is grounded where a run-independent protocol obligation determines the admissible forms and removing the closure would leave that obligation unserved by the remaining carrier — a transition the morphism requires left unrepresentable, or an invariant it holds no longer held. A closure nothing later branches on can still be load-bearing, where holding the value fixed is itself what the invariant asserts. The obligation has to survive removal of the proposed declaration too: a declaration and the machinery added alongside to mirror it do not ground one another. Where accumulated context or the user's utterance is instead what supplies the distinction, TYPES carries the invariant carrier shape and leaves its denotation runtime-bound. So in a sound closed answer coproduct the constructors name protocol-defined handling forms, while live ground supplies the occupant and whatever judgment-bearing payload it carries.

What makes a closure here cost more than the same closure in prose is that TYPES is runtime-normative: an enumerated case is read as the answer space itself, so the run reasons inside the author's catalog instead of against the situation in front of it. An over-specified entry is therefore repaired toward the least specific carrier that still preserves the independently grounded processing distinctions, and an open parameter preserves openness by transporting the runtime-grounded value without classifying it in advance. A further constructor is warranted on those same two counts and no others. That a classifier can already emit the label, or that a branch consuming the label arrives alongside the constructor, is neither of them — the distinction stays in the carrier that already carries it. This is the TYPES case of Context and Utterance as First-Class Ground (`premise/recognition-and-authority.md`); its branch-shaped sibling is Checkpoint Policy Stays at the Meta Layer (`premise/tiering-and-scope.md`).

Together the three tests yield two recurring consequences, and each has been mistaken for a gap in the type space:

- **A heuristic assignment owes the type layer no terminal.** Where a category is assigned by runtime judgment, "the judgment did not converge" is not a case the coproduct must enumerate. Supplying a terminal for it codifies a non-deterministic step into the rigid layer, and the loop that appears to stay open is a gated one: `.claude/principles/architectural-principles.md` §Three-Tier Termination settles that a cycle re-entering a Constitution gate is dialogue rather than a hang. What this exempts is the non-convergence itself, not the phase's side effects: where breaking off would leave partial state behind, that same section still requires an explicit withdrawal constructor, and that requirement does not weaken because the category was assigned by judgment.
- **A gap inside a closed coproduct is repaired by widening the value type first.** Widening a field changes the carrier's cardinality; adding a constructor changes the transition alternatives, so take the former wherever the new runtime value follows a path that already exists. Where the gap is that a field cannot *represent* a case — a singular field with no way to say "none" — widen the field so the missing case becomes a value and an existing constructor's guard absorbs it. Match the widening to the field's own cardinality: an optional field admits the empty case alone, while `Set(T)` additionally admits two or more, which is a further contract change wherever the phase logic assumed exactly one. A constructor is warranted only where PHASE TRANSITIONS genuinely gains a distinct processing path.

Two protocols carrying parallel machinery may still diverge here without either having a gap, where what differs is the fast layer's reach: a phase holding a Constitution gate can re-enter it and let the user's utterance settle the category, while a phase that is silent by contract cannot reach that channel. Silence removes the option of asking; what bounds the retry is the evidence. Where the phase re-assesses inputs fixed earlier, an identical retry can add nothing, so one attempt plus an unattributable record is the correct terminal. Where a silent retry could instead observe evidence the first pass did not, that same bound is premature and the record it writes is wrong.
