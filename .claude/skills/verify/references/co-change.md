# Co-Change Patterns

Protocol modifications require synchronized edits across multiple files. Any protocol change requires `plugin.json` version bump + `/verify`.

This table names co-change targets and the conditions that trigger them. Which of these couplings a static check actually guards is read from the verifier's layer files (`static-checks.js` names them) — a row here says what moves together, not that anything stops you from moving only part of it. [verification.md](verification.md) carries why the non-obvious checks exist and what to do when one fires.

| Change | Files to update |
|--------|----------------|
| New/modified phase | SKILL.md (formal block + prose) |
| New tool usage | SKILL.md (PHASE TRANSITIONS + TOOL GROUNDING: an `Op` constructor and its `grounding` arm; a `dispatch` operation also named by the declaration that decides when it hands off) |
| New loop option | SKILL.md (LOOP + terminal phase prose + Rules) |
| Delegation change | SKILL.md (isolation section), CLAUDE.md (delegation constraint) |
| Any protocol change | `plugin.json` version bump, then `/verify` |
| Dependent protocol interface wording in utility skills | Utility plugin `plugin.json` minor bump when onboard/reporting text now assumes a changed runtime interface in another protocol |
| New plugin added | `marketplace.json` (plugins array), plugin directory with `plugin.json`, `.agents/plugins/marketplace.json` (Codex marketplace — consumed by `scripts/install-codex.sh`), `<plugin>/.codex-plugin/plugin.json` (Codex manifest mirror), `scripts/package.js` `CODEX_SUBMIT_PLUGINS` (explicit submission set + its length guard — decide inclusion or record the staging) |
| New skill added to existing plugin | `SKILL.md`; `<plugin>/.claude-plugin/plugin.json` (version bump; description only when the plugin's routing cue changes); `<plugin>/.codex-plugin/plugin.json` (matching version in the same commit; `description`, `interface.shortDescription`, `interface.longDescription` only when the Codex routing cue changes); `marketplace.json` description only when the marketplace routing cue changes; `<plugin>/README.md` **and** `README_ko.md` skill table when the skill belongs on the plugin's public skill list — hand-maintained, no static guard, and the two language mirrors move together; the root `README.md` **and** `README_ko.md` utility inventories when the skill belongs on the repo's public utility list — same hand-maintained, no-static-guard, two-mirrors-together shape as the plugin tables, and neither table declares itself a subset, so an omission reads as the skill not existing; `scripts/package.test.js` (expected release-ZIP list); `package.js` (`FIRST_RELEASE_HIGHLIGHTS` Utility Skills selection only when the new skill should appear in the curated fallback used when scoped changelog groups are unavailable; `DESCRIPTION_OVERRIDES` only when the packaged frontmatter description exceeds 200 characters — an override replaces that description rather than escaping the limit, so it answers to the same one, and `package.test.js` asserts the packaged description against it; `PLUGINS` is derived from `discoverPlugins()`, no manual edit) |
| New protocol added | All of the above, plus: `scripts/load-protocols.js` (`CANONICAL_PRECEDENCE`, `CANONICAL_CLUSTERS` — hardcoded canonical lists; `PROTOCOL_FILES`/`CANONICAL_PROTOCOLS` are derived from filesystem/SKILL.md, no manual edit), ALL existing SKILL.md (precedence descriptions + distinction tables), onboard (`SKILL.md` Data Sources + `references/scenarios.md` + `references/workflow.md`), probe SKILL.md (`DeficitName` + `ProtocolId` type sets — the runtime-normative enumeration `/probe` scans against), README.md + README_ko.md, `.claude/skills/verify/references/review-checklists.md` (Epistemological Soundness — the per-protocol type-signature list). Decorative protocol-count phrases are NOT in this set — they stay count-free per CLAUDE.md §Settled Directions, and canonical-registry-derived test expectations update automatically |
| Protocol retired | The inverse of the "New protocol added" row, plus the surfaces that row does not reach because they consume a protocol rather than list it — sweep with hidden directories included (`rg --hidden`), since `.claude/` is skipped by default: project skills declaring it as a `skills:` frontmatter dependency or composing its `/command` (`.claude/skills/formal-review` — fold the retired lens in-skill or drop it), `.claude/skills/verify/SKILL.md` Integration Notes, `.claude/principles/project-profile-calibration.md` bounded-zone lists, any other protocol's TYPES route constructor or prose that hands off to the retired command (route to the absorbing neighbor named in the retirement commit), onboard quiz distractors and Onboarding Pool, `anamnesis/scripts/hypomnesis-write.mjs` identifier maps, `scripts/install.sh`, every sibling plugin `README.md` + `README_ko.md` + `docs/scenarios.md` "adjacent protocol" mentions. Dated material under `design/` is a then-record and stays. The retirement commit body carries the criterion, the rejected retype options, and the absorption map |
| Precedence change | ALL SKILL.md precedence descriptions, README.md + README_ko.md (concern-cluster workflow) |
| Initiator taxonomy change | ALL SKILL.md (distinction tables + Rule #1), READMEs, `review-checklists.md` |
| Protocol nudge pattern, gate or convergence rendering, or any other Epistemic Ink element change | the Epistemic Ink output style, which ships in the cc-plugin marketplace as `ink-figure/styles/epistemic-ink.md` (moved there by ROO-114) — a change lands in that repository with its own version bump; on this side, the protocol `SKILL.md` restatements the change reaches (see the Round composition / Form feedback row) |
| Convergence-awareness nudge wording | `.claude/principles/architectural-principles.md` (Inter-Protocol Guidance) + `premise/gate-design.md` (Full Taxonomy Confirmation, source of truth) |
| Gate interaction pattern change | ALL SKILL.md Rules + PHASE TRANSITIONS + TOOL GROUNDING + phase prose + plugin.json version bumps |
| Relay interaction pattern change | SKILL.md TOOL GROUNDING + `premise/gate-design.md` (Convergence Evidence, source of truth) + the Lean audit's TOOL GROUNDING rules (`lean/Audit/Check.lean`) and their fixtures (`lean/Tests`) when the change moves what they judge + plugin.json version bumps |
| TOOL GROUNDING vocabulary or realization change | `lean/EpistemicProtocols/ToolGrounding.lean` (canonical) and its `Theorems.lean` + the copy opening every protocol block's TOOL GROUNDING, in the same commit + the Lean audit's TOOL GROUNDING rules and fixtures when an annotation they read changes + `docs/structural-specs.md` (§Lean Notation, §TOOL GROUNDING Annotation Vocabulary) + plugin.json version bumps for every protocol |
| Derived principle addition | the premise document that owns the principle's family (`premise/gate-design.md`, `premise/instruction-authoring.md`, or `premise/recognition-and-authority.md` — source of truth, with the derivation annotated there) + SKILL.md Rules inline summary in protocols scoped-in per the principle's Scope block (self-contained inline wording; no external reference to rule or premise files) + plugin.json version bumps for affected plugins |
| Architectural principle addition | the general principle → `premise/tiering-and-scope.md` (new tier-tagged section; source of truth) **only when it holds without presupposing a protocol layer — one stated in terms of protocols, their composition, or their coexistence with host tooling goes to `.claude/principles/architectural-principles.md` outright** + this project's instance, if any → `.claude/principles/architectural-principles.md` + cascading reflection in cited rule/principle files (e.g., `.claude/principles/project-profile-calibration.md`) + SKILL.md inscription **only when gate annotations are directly affected** (e.g., new TOOL GROUNDING entry, new Rule, new Phase prose section — substrate boundary touch is one such case). Profile-layer reclassification alone (rule/principle-file changes without gate annotation changes) does NOT trigger SKILL.md updates — those follow per-protocol future stages pending accumulated use evidence. Plugin.json version bumps only for plugins whose SKILL.md actually changes. If premise layer purification is involved (subsumed paragraph removal), perform removal in the same commit to preserve principle homogeneity |
| Gate axis purification (single TOOL GROUNDING axis) | ALL SKILL.md TOOL GROUNDING (split `(extension)` entries for conditional specialization) + removal of any obsolete dual-axis annotation section + `premise/interaction-factorization.md` (§Interaction Kind Factorization, source of truth) + `.claude/principles/architectural-principles.md` §Authority at Protocol Checkpoints (source-defined authority and checkpoint requirements) + `premise/gate-design.md` (§Loop Continuity / §Full Taxonomy Confirmation, source of truth) + `.claude/principles/project-profile-calibration.md` (§Scope Boundary) + `premise/calibration-methodology.md` + verify scripts (`single-axis-soundness` check; removal of any structural check enforcing the obsolete annotation section) + utility skill references + READMEs / agents / styles citing the old regret-axis vocabulary + plugin.json version bumps for affected plugins |
| SKILL.md frontmatter description change | `scripts/package.js` DESCRIPTION_OVERRIDES — remove an existing override once its source description fits 200 characters, and shorten an over-limit source rather than adding one; the plugin-level descriptions (`<plugin>/.claude-plugin/plugin.json`, `<plugin>/.codex-plugin/plugin.json` `description` + `interface.shortDescription` + `interface.longDescription`, `.claude-plugin/marketplace.json`) when the wording a user or router reads changes. The type signature lives in the body's opening paragraph, not the description |
| `/realize` case file or invocation line reused by an `/outcome` case (the `scaffold.sh`, a variant's `prompt.md` or `oracle.md`, a `targets.<t>.invocation` line in `harness.config.json`) | the `/outcome` case under `.claude/skills/outcome/cases/` that names it in `case.json`: its items are read against those bytes, so the change is a new case directory, not a new digest written into the old one. The digests it was frozen against are that case's `case.json` `frozenAgainst` / `frozenInvocation` |
| Hypomnesis store write pipeline change (mjs harness) | `anamnesis/hooks/hooks.json` (shared lifecycle-hook registration) only when the registration changes — the registered events, the dispatched command, `async`, or the top-level `description` naming what is indexed; the affected writer/dispatcher under `anamnesis/scripts/`; `anamnesis/skills/recollect/SKILL.md` Scan section plus the affected harness reference under `references/` (read-side pattern) only when the written artifact's path, filenames, frontmatter fields, the canonical form of a value the read side ranks, greps or dedups on, or the schema/value semantics consumed by capture-outcome qualification change; both plugin manifests (matching version bump); and the affected Hypomnesis test under `anamnesis/scripts/` |
| Axiom change (any foundational principle in `premise/recognition-and-authority.md`, `premise/interaction-factorization.md`, or `premise/gate-design.md` / Gate Integrity definition or summary) | `premise/recognition-and-authority.md`, `premise/interaction-factorization.md`, `premise/gate-design.md` (source of truth, split by axiom — no in-repo restatement to keep in sync) + any `.claude/principles/*` section whose project-local binding cites the changed kernel |
| Instruction-authoring principle change (Zero-Shot Instruction Preference / White Bear Avoidance / Subtraction at Revision Time and its nested Deletion by Default and Actionable revision criterion / Currency is not Support-Integrity / Audience Reach / Direction over Accumulated Workload / Conflicting Instructions / Where a Repair Lands) | `premise/instruction-authoring.md` (source of truth) + any section in `.claude/principles/architectural-principles.md` or `.claude/principles/safeguards.md` carrying this project's own grounding instance of the changed principle (the instance does not travel; the principle is not restated) + `premise/gate-design.md` §Guard consistency when the change touches the conflict-repair boundary the two share + `.claude/rules/protocol-repair.md` and the premise index entry in `route/scripts/route-premise.mjs` when the change renames or retires §Where a Repair Lands, or moves the moment that section binds at — the rule reaches it by section name, the index entry by that moment, so each goes stale on its own trigger + `.claude/rules/instruction-surface-revision.md` when the change renames or retires §Override Gate, §Subtraction at Revision Time, or §Where a Repair Lands, or moves the moment any of them binds at — it reaches them by section name |
| Mission/vision wording change | `CLAUDE.md` (maintainer umbrella), `docs/mission-bridge.md` (audience boundary + derivation rule), `README.md` + `README_ko.md` (public framing), `.claude-plugin/marketplace.json` top-level `description` (marketplace derivation); verify runtime users still rely on `SKILL.md` + plugin descriptions rather than mission docs |
| Editing/Git convention change | The carrier is split by the moment the convention binds. A notation or editing convention that binds per turn, and the release tag → `.claude/rules/editing-conventions.md` (primary) → `CLAUDE.md` (reference). A convention that binds at a contributor-workflow step — commit subject, branch naming, PR body language → `ONBOARDING.md` §Contribution Workflow / §Conventions, its sole carrier. A change to the commit subject additionally reaches `scripts/generate-changelog.js` `COMMIT_RE`, which parses that subject for release-note grouping |
| Intent record convention change (what the record carries, where this repository keeps it, how it closes) | `docs/intent-record.md` (source of truth) + `AGENTS.md` §Settled Directions **Intent binding** (the one-line pointer and this repository's home — keep it a pointer, not a copy of the convention) + `.claude/rules/instruction-surface-revision.md` (the paragraph routing a change's direction to the record, and the order clause). No static check guards this set |
| Round composition / Form feedback wording change | every protocol `SKILL.md` `## Rules` entry carrying it ("Round composition", "Form feedback", each keeping its own ordinal) + that protocol's `references/round-composition.md` for Round composition + the TOOL GROUNDING `(track)` entry where a protocol restates durable recording. The reach/residue principle Form feedback compiles is stated domain-free in `premise/approach-verification.md` §Reach and residue; the rule does not reference it, because a packaged SKILL.md carries no premise document. `emit-load-discipline` guards only that each label exists, not that the entries agree, so the whole set moves in one commit by hand + plugin.json version bumps for every affected plugin |
