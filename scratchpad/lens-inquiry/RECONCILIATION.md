# 화해 — 다섯 렌즈의 반박 ⨾ 종합

**심문 대상**: 기존 `/apportion`(Merismos, `GoalPlanUncompiled`)과 `/conduct`(Hyphegesis,
`MethodUnderdetermined`)를 대체할 새 프로토콜을 신설해야 하는가 — 합집합 병합이 아니라 재타이핑으로.

**방법**: `/conduct` 가 설계한 ConductedMethod. 판정 리전 = 이동 다섯(M1·M2·M3·M4·M5),
독립 `isolated`, 화해 `Compose(adversarial_refute ⨾ synthesis)`, 종료 `single_pass`.
생성 리전 = M7(`/elicit`), 실행 세션이 직접 수행.

**기준 커밋**: `444d776b`. **인계물**: 신설 여부의 판정 — 신설한다면의 초안이 아님.

**실행 기질**: 실행 세션(Stint) 하나 + 격리 서브에이전트 다섯. 다섯은 서로의 산출물을 보지 못했고,
각자 자기 렌즈 지시와 M7 산출물만 받았다. M3·M4 는 M7 산출물 없이(계획대로) 독립 수행.

## 1. 수렴점 — 서로를 보지 못한 채 같은 곳에 도달한 것

격리 실행이었으므로, 아래 항목들은 합의가 아니라 **독립 도달**이다. 그것이 이 심문의 주요 소득이다.

### 수렴 ① — 선례(`/elicit`)의 성립 기제가 이 사례에 없다 (M1·M4 독립)

두 렌즈가 서로 다른 어휘로 같은 텍스트 증거에 도달했다.

- **M1(타입)**: euporia 의 성공 기제는 **통약 가능한 범용 캐리어**였다 —
  `Coordinate = {name, default, question, basis}`(`elicit:52`), `Axis = String — emergent label`
  (`elicit:70`), `D[] = List(DimensionProjection)` "cycle-emergent; no fixed taxonomy"(`elicit:50`).
  옛 두 결손은 닫힌 coproduct 가 아니라 **열린 파라미터화 술어의 두 사례**였다. `/apportion` 의
  `SpanFit`(의무·적합 판단)과 `/conduct` 의 `Gen(order)`(그래프 위상 판단)에는 그런 공통 캐리어가
  없다.
- **M4(해석학)**: `Axis = String -- emergent label; examples: "intent", "goal", ...` 이 곧 증거다 —
  clarify 와 telos 는 **하나의 동일한 모피즘이 두 라벨을 쓰고 있었을 뿐**이다.

**실행 세션 검증**: `elicit:70` 원문 확인 — 일치.

### 수렴 ② — 합병은 `topology_free` 를 두고 실패한다 (M1·M4·M5 독립, 세 축)

- **M1(타입)**: openness criterion 상 `topology_free`(`apportion:120`)의 근거는 코도메인
  `ConditionBearingUnitPlan` 이 pre-conduct 라는 모피즘 자체의 선언이며, 술어를 제거해도
  "미결정 미래 토폴로지에 계획이 이식 가능해야 한다"는 의무가 살아남는다. 후보 B 는 자신이
  반증해야 할 술어를 반증하지 못한 채 전제로 삼는 **순환**이다.
- **M4(해석학)**: `merismos:376` Core Principle "Apportion over Order" + `:569` Rule 2 "Apportion,
  do not order … The emitted artifact is pre-conduct by construction" — 이 저장소 자신이 **명시적
  비동일성을 이미 문서로 확정**해 두었다.
- **M5(근거 접근)**: 두 프로토콜은 경계 너머로 서로 **다른 종류**의 근거를 관리한다 —
  `/apportion` 은 판단의 결과를 내용째 굽고(copy-in), `/conduct` 는 아직 답 없는 질문의 **구조만**
  굽는다(`Slot(T)`, Rule 16 `conduct:473` "a contract of structure, not content"). 하나의 타입으로
  재타이핑하면 이 분업을 **파일 내부 경계로 되살려야 한다**.

**실행 세션 검증 — 세 렌즈가 말한 것보다 강함**: `topology_free` 는 규칙이 아니라
**수렴 불변식의 연접항**이다. `hard_invariants_hold(Λ) ≡ … ∧ Λ.invariant_status.plan_conditions_topology_free`
(`merismos/skills/apportion/SKILL.md:136`). 즉 병합이 이 술어를 약화시키면 `/apportion` 은 수렴
자체를 못 한다.

### 수렴 ③ — 기질 변화(Stint)는 이미 흡수돼 있고, 남은 자리는 설계가 **거절한** 자리다 (M1·M2·M4·M5 독립, 네 축)

- **M4**: `Gen(routing)` 의 `handoff_to_span`(`conduct:72`)이 이미 "이 세션의 컨텍스트를 공유하지
  않는 별도 지평으로 넘어간다"는 구조를 갖는다. 흡수 가능한 변화이지 재타이핑 근거가 아니다.
- **M1**: `handoff_to_span` 은 여섯 블록을 관통하는 **완전히 폐쇄된 타입**
  (`conduct:63,72,107-108,243-244,279`). 후보 C 의 정적 부분은 `SpanExternalization` 페이로드
  확장으로 충분하고, 동적 부분(경계 이전 진행 중 갱신)은 `conduct:462` Rule 3 를 위반하지 않고는
  담을 수 없다 → **감시(monitor) 모양의 제3의 직교 프로토콜**이 필요하다는 뜻이지 두 프로토콜을
  대체할 근거가 아니다.
- **M5**: 미흡수 잔여는 "넘어감에서 무엇이 살아남는가" 일반이 아니라 구체적으로
  **far-side compile-back** 이며, 이는 발견된 누락이 아니라 `conduct:493` 의 `cross-span-absorption`
  가드가 **정면으로 선언한 범위 밖**이다. 새 프로토콜이 그 자리를 메우면 그 가드가 이름 지은
  반패턴을 스스로 범한다.
- **M2(계보)**: 그 자리를 겨눴던 프로토콜이 **이미 있었고 은퇴됐다** — `/distill`(Diylisis),
  `3f131e9d`. 은퇴 사유는 "저작 세션은 자기 안에서, 수신 세션만이 관측할 수 있는 속성을 검증할 수
  없다"는 구조적 불가능성이었고, 기능은 프로토콜이 아니라 `AGENTS.md` 포인터-우선 라우팅 +
  `/conduct` 의 가드된 `handoff_to_span` 으로 재분배됐다.

**실행 세션 검증**: `conduct:462` Rule 3 원문 "It has no runtime monitoring surface" 확인 — 일치.
`conduct:493` 가드 원문 "both belong to the receiving span" 확인 — 일치.

### 수렴 ④ — 제안의 판별 특징(draft-first)이 이미 한쪽에 있다 (M7·M3·M4 독립)

셋이 같은 사실에 도달했다: `/conduct` 는 이미 draft-first 다(`conduct:12`, 불변식 `:142`,
Phase 2 `:403`). M4 가 한 단계 정밀화한다 — **draft-first 가 결여된 곳은 Merismos Phase 1 하나뿐**
이고, Merismos Phase 2 도 이미 전체를 pre-gate 로 제시한다(`:517`).

## 2. 반박 — 각 평가를 나머지에 대어 무엇이 견디는가

### 반박 대상 A — M3 의 차수 논변

> **주장**: 판단 차수가 `O(유닛수+k)` → `O(1+j+k)` 로 바뀌고, `j ≤ 유닛수` 이므로 이 부등식은
> 경합 비율과 무관하게 **항상** 성립한다.

**견딘다.** 다른 넷 중 누구도 이 부등식을 반박하지 않았고, 구조 독해(`apportion:487` 직렬 per-unit
루프 vs `conduct:403` whole-topology draft)가 이를 뒷받침한다.

**그러나 결론으로 가는 다리가 끊긴다.** M3 자신의 §2 가 그 다리를 이렇게 쓴다: *"재타이핑 제안의
실질은 conduct 가 이미 가진 draft-first 메커니즘을 apportion 의 유닛-자르기에도 확장 적용하는 것."*
그것은 **Merismos Phase 1 의 내부 개정**이며, 신설이 필요하지도 충분하지도 않다. M4 의 판정 (2)와
codex 4차의 최소 수리가 독립적으로 같은 자리를 지목한다.

**판정**: 사실 주장은 살아남고, **그것이 신설을 지지한다는 추론은 탈락**한다.

### 반박 대상 B — M3 의 읽기 비용 논변

> **주장**: euporia 선례(clarify 418줄 + telos 393줄 = 811 → elicit 361줄, 55% 감소)가 진짜
> 재타이핑이 합집합보다 훨씬 작아질 수 있음을 실증한다.

**탈락한다.** M1 과 M4 가 서로를 보지 못한 채, 그 55% 압축이 **무엇 때문에 가능했는지**를 각각
특정했다(수렴 ①): 통약 가능한 범용 캐리어 / 동일 모피즘의 두 라벨. 그 기제가 이 사례에 없으므로
선례는 이 사례의 증거가 되지 못한다. M2 는 한 겹 더 얹는다 — euporia 인쇄 커밋(`29249c57`)은 결과만
인쇄하고 **비함의 논증을 원장에 남기지 않았으므로**, 이 저장소 자신의 Ledger binding 기준으로는
근거 서술이 가장 얇은 재타이핑 사례다.

M3 자신도 같은 방향의 유보를 달았다("apportion/conduct 는 기능적으로 더 직교적이라 같은 압축률
재현은 근거 약함"). 반박은 그 유보를 확정한다.

### 반박 대상 C — M3 의 조건 (1)

> **조건**: 병합 설계가 draft-first 를 유닛-자르기까지 확장하되, **단일 모드 요청에서는 반대쪽
> 절반이 스캔 대상에도 오르지 않고 조용히 relay/생략되어야 한다**(활성화 게이트의 깨끗한 모드 분리).

**이 조건은 자기 자신을 무효화한다.** M1 §2.1 이 후보 B 에 dispatch-structure test 를 적용한 결과:
후보 B 는 형식적으로 coproduct 자격을 통과하지만, **그 통과 자체가 반증**이다 — 진짜 재타이핑이면
옛 구분에 대해 균일 처리로 붕괴해야 하는데, B 는 옛 구분을 두 생성자로 **보존**한다. 그것은
"하나의 파일에 든 두 프로토콜"이다.

M3 의 조건 (1)이 요구하는 "깨끗한 모드 분리"가 정확히 그 보존이다. 즉 **M3 의 통과 조건이 M1 의
실격 기준이다.** M3 은 자기 지평 한계에서 타입 판정을 명시적으로 자기 소관 밖으로 선언했으므로
("재타이핑의 개념적 정당성 자체를 판정하지 않는다"), 이 충돌은 M1 쪽에서 해소된다.

**판정**: 탈락. 그리고 이것이 4 대 1 을 다수결이 아니라 **구조적 결론**으로 만드는 지점이다.

### 반박 대상 D — M7(실행 세션 자신)의 horizon fit 주장

> **M7 주장**: `/apportion` 은 후보 C 를 포함하지 않는다 — **정반대다**. horizon fit 은 넘어감을
> 마련하는 게 아니라 불필요하게 만든다.

**M5 가 반박했고, M5 가 옳다.** horizon fit 은 넘어감을 **단위 내부에서만** 불필요하게 만든다.
`/apportion` 은 애초에 하나의 목표가 하나의 지평에 맞지 않을 때 여러 단위로 자르는 프로토콜이므로
**단위 사이의 경계는 전제돼 있고**, 그 경계를 `park_carrier` + `NavigationBlock` 발행으로 **이미
마련한다**. 즉 하나의 프로토콜이 "예방"과 "마련" 두 전략을 서로 다른 소재지에서 동시에 들 수 있음이
현재 코드베이스에 실증돼 있다.

**실행 세션 검증**: `apportion:160` `locator(C) … substrate-neutral by construction: the identity is
whatever the carrier-creating call returned, so this type never names what performs that call` /
`:161` `NavigationBlock { purpose_frame, canonical_locator, dereference_instruction, snapshot_anchor,
grounding_instruction }` — 원문 확인, 일치. **M7 의 주장을 철회한다.**

이 정정은 방향을 바꾸지 않고 **강화**한다: 화해가 새 프로토콜을 요구한다는 논거가 하나 더 줄었다.

### 반박 대상 E — M2 의 계보 판정

> **주장**: `243ff8f0`(`/attend` → Merismos)이 이 저장소가 유일하게 목격자 쌍으로 입증한 재타이핑
> 전례이고, 그 입증은 **병합 기각** 방향으로 쓰였다.

**견딘다 — 그리고 실행 세션의 확인이 한 겹 더 얹는다.** 커밋 원문 확인:

> "`GranularityUnderdetermined` 와 `ExecutionBlind` 는 서로를 함의하지 않으므로(단위는 명확한데
> 술어가 없는 경우, 다단위 계획인데 자율 루프가 없는 경우가 각각 한쪽만 성립) 두 결손을 한
> 프로토콜에 겸하게 하면 단일 목적 원칙이 깨진다. 따라서 확장이 아니라 전면 재타입을 택했다."

**같은 커밋이 두 가지 선례를 동시에 세운다**: (a) 이 저장소의 가장 강한 **재타입** 선례이면서
(b) 가장 강한 **"한 프로토콜에 두 결손을 겸하지 말라"** 선례다. 그리고 그 재타입은 결손 하나를
**버리고** 다른 하나를 취한 것이지 둘을 **합친** 것이 아니었다.

**여기서 나오는 일반 형태** — 이 저장소의 재타이핑은 두 형태뿐이었다:
1. **열린 술어로의 승격**(euporia): 두 옛 결손이 하나의 열린 파라미터화 술어의 두 **사례**가 됨.
   합집합이 아니라 상위 술어.
2. **결손 교체**(`243ff8f0`): 옛 결손을 버리고 새 결손을 취함. 옛것은 **남지 않는다**.

**둘 → 하나로 합친 전례는 없다.** 제안된 형태는 이 저장소가 한 번도 밟지 않은 세 번째 형태다.

### 반박 대상 F — M4 의 정체성 논변

> **주장**: 정체성은 (결손, 개시자, 모피즘, 도메인) → 해상 타입의 시그니처가 담지하고, 루프의
> 제시 형태(draft-first)는 그 아래 층이다.

**견딘다, 무반박.** M1 이 블록 층위에서 같은 구분을 쓰고, M3 은 이 질문을 자기 소관 밖으로
선언했으며, M5 는 건드리지 않았다. M1 §2.5 가 시그니처 합성을 실제로 시도해 세 자리 전부에서
정보 손실을 보인다: initiator `User`(`apportion:71`) vs `Hybrid`(`conduct:338`) — 어느 쪽으로
합쳐도 손실. 도메인 곱 `ExecutionHorizon` 과 `MoveGround` — 파생 관계 근거 없음, 재타이핑이 아니라
4항 연접. 코도메인 — 오늘 이미 존재하는 합성 엣지(`apportion:576` Rule 9 / `conduct:477` Rule 20)로
도달 가능한 값의 재포장.

## 3. 종합 — 살아남은 것

### 판정

**신설하지 말아야 한다.** 제안된 "합집합이 아니라 재타이핑" 형태로는.

이것은 4 대 1 의 다수결이 아니다. 유일한 찬성(M3)의 **통과 조건이 형식 층에서 재타이핑 자격을 스스로
무효화**하고(반박 C), 그 근거로 든 선례는 성립 기제가 특정되면서 이 사례의 증거가 아님이
드러났으며(반박 B), 살아남은 사실 주장(차수 개선)은 신설이 아니라 **Merismos Phase 1 의 draft-first
화**를 지지한다(반박 A).

### 살아남은 명제 여덟

1. 두 결손은 **상호 비포함**이다 — `243ff8f0` 과 동형의 목격자 쌍이 양쪽에 서식한다.
2. 이 저장소의 재타이핑은 **결손 하나 → 결손 하나**뿐이었다. **둘 → 하나의 전례가 없다.**
3. `/elicit` 선례의 압축 기제(통약 가능한 범용 캐리어 / 동일 모피즘의 두 라벨)는 이 사례에 **없다**.
4. 병합은 `topology_free` 를 두고 유지·폐기·약화 **세 갈래 전부에서 실패**한다. 그 술어는 산문이
   아니라 **수렴 불변식의 연접항**(`apportion:136`)이다.
5. 제안의 판별 특징(draft-first)은 이미 `/conduct` 에 있고, 결여된 자리는 **Merismos Phase 1
   하나**다.
6. 기질 변화(Stint)는 근거 접근 축에서 **이미 흡수**돼 있다(`NavigationBlock` 은
   substrate-neutral, `apportion:160`). 흡수 안 된 자리(far-side compile-back)는 설계가
   `conduct:493` 가드로 **명시적으로 거절한** 자리다.
7. 그 자리를 겨눴던 프로토콜이 **이미 있었고 은퇴됐다**(`/distill`, `3f131e9d`). 새 프로토콜은
   그 은퇴 결정과 `conduct:493` 가드를 **동시에 뒤집어야** 한다.
8. 인지 부하 축의 차수 개선은 **참이고 조건 없이 성립**하지만, 그것을 가져오는 것은 신설이 아니라
   Merismos Phase 1 의 개정이다.

### 반박이 남긴 것 — 실재하는 잔여 둘

판정이 신설 반대라고 해서 제안이 겨눈 자리가 비어 있다는 뜻은 아니다. 다섯이 서로를 보지 못한 채
**같은 두 자리**를 남겼다.

**잔여 ① — "다음 행동"이 어느 타입에도 1급 필드로 없다** (M5 가 특정, M7 이 다른 경로로 근접)

`premise/session-and-handoff.md` §Resumption Cues 는 이것을 "task-resumption 연구가 가장 직접
지지하는 하중 요소이자, 가장 자주 빠지는 것"이라 못박는다. 그러나 `NavigationBlock` 의
`grounding_instruction` 은 "어떻게 역참조하는가"를, `CheckpointBrief` 는 "무엇을 물을 것인가"를
구울 뿐, **"다음에 무엇을 하려던 참이었는가"는 굽지 않는다.** M5 는 이것이 `move_assignment` /
`checkpoints` 의 순서에서 파생 가능한지는 열려 있다고 표시했다.

규모: 새 프로토콜이 아니라 **기존 내비게이션-블록류 타입에 대한 작은 필드 추가**.

**잔여 ② — "실행자 할당"이 어느 프로토콜의 범위도 아니다** (M7 이 발화 분석에서 특정)

원 질문의 제안문은 "작업 분할·**실행자 할당**·흐름 지휘를 한 번에 구성한다"고 쓴다. 셋 중 가운데가
현재 어디에도 없다: `/apportion` 의 `CapabilityRequirement` 는 "descriptive only, executor-neutral"
(`apportion:98`)이고, `/conduct` 의 `routing` 은 산출물이 **어디로 가는지**를 정하지 실행자를
바인딩하지 않는다.

`goal_research_stint_conducting.md` 가 이 자리에 직접 답한다: **"capability-named plan + late
binding"** — 역량은 계획에 이름 짓고 구체 실행자는 런타임에 바인딩하며, 정체성이 정확성에 영향을
줄 때만 선택적으로 고정한다. 이는 두 프로토콜의 현재 설계와 **정합한다** — 즉 잔여 ②는 프로토콜의
결손이 아니라, 제안문이 프로토콜 범위 밖의 것을 섞어 넣은 것일 수 있다.

M2 의 `/distill` 은퇴 사유가 여기에 경고를 건다: 저작 세션은 수신 세션만이 관측할 수 있는 속성을
검증할 수 없다. 실행자 할당을 계획에 굽는 설계는 그 은퇴가 확정한 불가능성을 다시 밟을 위험이 있다.

## 4. 발산점 — 화해가 해소하지 못한 것

**M3 대 나머지 넷은 실질 발산이 아니다.** 반박 A 가 보인 대로, M3 의 사실 주장은 살아남되 다른
결론(Merismos Phase 1 개정)을 지지한다. 같은 사실의 다른 귀결이지 상충이 아니다.

**진짜 발산은 잔여 둘의 처방 규모에서 갈린다.** 넷이 각각 다른 크기를 가리켰고, 화해에는 이를
결정할 근거가 없다.

| 렌즈 | 처방 | 규모 |
|---|---|---|
| M5 | 내비게이션-블록류 타입에 **작은 필드 추가** | 최소 |
| M4 | `Gen(routing)` 에 값 추가 또는 `handoff_to_span` 의 계약 능력 확장 | 소 |
| M2 | "덧대기" — 기존 축 확장 **또는 비-프로토콜 표면 흡수**(`/distill` 선례가 후자를 밟았음) | 소~중, 갈림 |
| M1 | 정적 부분은 `SpanExternalization` 페이로드 확장으로 충분; **동적 부분이 실재한다면** compile-then-handoff 가 아닌 **monitor 모양의 제3의 직교 프로토콜** | 최대 |

M1 의 최대안은 조건부다 — "경계 이전 진행 중 갱신"이 실재할 때만 발동하며, 그것은 `conduct:462`
Rule 3("It has no runtime monitoring surface")을 위반하지 않고는 `/conduct` 에 담을 수 없다.
**그 동적 요구가 실재하는지는 이 심문이 판정하지 않았다.**

## 6. 트레이스 계약 (공개 의무)

**잔여** — 설계 시점 아홉 슬롯 전부 "초안이 이유를 대고 사용자가 그대로 받음". 게이트에서 구성된
값 0, 근거 없이 기본값으로 떨어진 슬롯 0. 실행 시점 추가 잔여 없음.

**저하** — 설계 시점 `substrate_infeasible` 1건(워커의 서브에이전트 감독 금지 규약의 과대범위
판정)은 실행 시점에 해소됐다: 격리 서브에이전트 다섯을 실제로 운용했고 `independence: isolated`
가 실현됐다. `independence_relaxed` 0건. **다섯은 서로의 산출물을 보지 못했다.**

**커버리지 한계 — `single_pass` → `no_retry` 가 실제로 물었다.** 반박 단계에서 렌즈를 되돌려
보내야 할 발견이 하나 나왔고, 두 번째 패스가 없어 보내지 못했다:

> **M3 에게 물었어야 할 것**: "당신의 통과 조건 (1)(단일 모드 요청에서 반대쪽 절반이 스캔 대상에도
> 오르지 않는 깨끗한 모드 분리)이, M1 이 재타이핑 실격 기준으로 쓴 것(옛 구분을 두 생성자로
> 보존 = 하나의 파일에 든 두 프로토콜)과 같은 것이다. 이 충돌 앞에서 당신의 조건부 찬성이
> 유지되는가?"

화해는 M1 쪽에서 이 충돌을 해소했다(M3 이 타입 판정을 자기 소관 밖으로 명시 선언했으므로). 그러나
그것은 **M3 이 답한 것이 아니라 화해가 대신 답한 것**이며, 이 심문의 구조가 그 답을 M3 에게 물을
수 없게 되어 있다. 사용자가 두 번째 패스를 원한다면 그것이 그 자리다.

**종료 근거** — 두 리전 모두 `single_pass` 라 정지 파라미터가 필요 없다.

**이 심문이 주장하지 않는 것** — 잔여 둘의 처방 규모. 그것은 §4 의 발산으로 열려 있고, 화해에는
그것을 결정할 근거가 없다.

**실행 세션이 직접 검증한 인용** (관계자 보고를 그대로 중계하지 않기 위해):
`apportion:136` · `:148` · `:160` · `:161` · `:376` · `:569` · `conduct:462` · `:493` ·
`elicit:70` · 커밋 `243ff8f0` 메시지 전문. 전부 원문과 일치. **M7 의 horizon-fit 주장 하나는
M5 의 반박에 따라 철회됨**(§반박 D).
