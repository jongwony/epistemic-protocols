# Epharmoge — /contextualize (ἐφαρμογή)

결과가 닿는 모든 곳에서 어긋남을 찾아 한 장에 보이고, 정한 고침을 반영한다 (ἐφαρμογή: 적용, 맞춤)

> [English](./README.md)

## Epharmoge란?

그리스어 ἐφαρμογή(적용/맞춤)의 현대적 재해석으로, **결과가 적용되는 상황에 맞는지를**, 결과가 닿는 모든 곳과 결과가 실어야 했던 모든 의도까지 따라가 확인하는 프로토콜이다. 올바름이 적합을 뜻한다고 가정하지 않는다. 결과는 이 세션의 산출물일 수도, 다른 곳에서 온 것 — 다른 세션의 작업, 문서, 계획 — 일 수도 있다.

### 핵심 문제

결과가 올바르면서도 적용되지 않을 수 있다. 올바름만으로는 적용 가능성이 보장되지 않는다(`ApplicationDecontextualized`). 환경 가정, 관례 불일치, 범위 초과, 결과가 실어야 했지만 싣지 않은 의도 등이 기술적으로 올바른 출력을 대상 맥락에 부적합하게 만들 수 있다. 결과를 만든 AI 는 "끝냈다" 를 "맞다" 로 여기기 쉽고, 사용자는 결과가 닿는 곳을 다 떠올리지 못한다 — 그래서 격차는 드러날 때까지 숨어 있다.

### 해결책

**올바름보다 적용 가능성**: AI 가 결과가 닿는 모든 곳 — 그것을 읽거나 쓰는 쪽, 사본과 이웃, 읽는 사람, 돌아가는 환경 — 과 대화 속에서 결과가 실어야 했던 모든 의도까지 따라가, 아무것도 바꾸지 않고 관측하며 닿지 못한 곳은 이름으로 남긴다. 맞지 않는 곳은 모두 한 장에 사용자의 상황에서 생기는 구체적 결과와 함께 오르고, 사용자는 한 턴으로 답한다 — 이렇게 고침, 이 이유로 둠, 안 씀, 이 결과가 고칠 일이 아님. 고침이 반영되고 결과를 다시 읽으며, 열린 것이 없으면 따로 "끝" 을 묻지 않고 완수한다. 탈맥락화된 실행을 맥락화된 실행으로 변환한다.

### 다른 프로토콜과의 차이

| 프로토콜 | 주도자 | 타입 시그니처 |
|----------|--------|---------------|
| Aitesis | AI-guided | `ContextInsufficient → SufficientContext` |
| Merismos | User-initiated | `GoalPlanUncompiled → ConditionBearingUnitPlan` |
| **Epharmoge** | **AI-guided** | **`ApplicationDecontextualized → ContextualizedExecution`** |
| Katalepsis | User-initiated | `TargetUngrasped → VerifiedUnderstanding` |

### Aitesis와의 차이

| 관점 | Aitesis | Epharmoge |
|------|---------|-----------|
| 타이밍 | 결과가 있기 전 | 결과가 있은 뒤 |
| 방향 | AI가 스스로 모으고 사용자의 Unknown을 돌려줌 | AI가 결과를 그것이 닿는 모든 곳과 사용자의 맥락에 대조함 |
| 축 | Context fitness | Context fitness |
| 결핍 | `ContextInsufficient` | `ApplicationDecontextualized` |
| 해소 | `SufficientContext` | `ContextualizedExecution` |

같은 축(context fitness), 반대 타이밍, 다른 대상 — 결과가 있기 전엔 AI에게 부족한 것, 뒤엔 결과가 맞는지. Aitesis는 "내가 스스로 닿을 수 있는 것은 무엇이고, 당신 몫은 무엇인가?"를 묻고, Epharmoge는 "이 결과 — 내 것이든 누구의 것이든 — 가 닿는 곳에 실제로 맞는가?"를 묻는다. 상호 보완적이지, 중복이 아니다.

## 프로토콜 흐름

```
한 바퀴 → 결과가 닿는 모든 곳 관측, 정해진 고침 반영, 다시 관측 (비표시)
한 장   → 모든 어긋남을 한꺼번에, 구체적 행동 · 맞는 것 · 닿지 못한 곳 · 바뀐 것과 함께 (질문 하나)
답      → 한 턴이 여럿을 정한다; 다음 바퀴가 반영한다
완수    → 열린 것이 없으면 닫는 한 장, 따로 "끝" 없음
```

## 불일치 신호

| 신호 | 탐지 |
|------|------|
| 환경 가정 | 결과가 현재 맥락에서 검증되지 않은 환경 상태를 가정 |
| 관례 불일치 | 결과가 일반적 모범 사례를 따르지만 프로젝트에 로컬 관례가 존재 |
| 범위 초과 | 결과가 관찰된 사용 사례가 요구하는 것보다 많거나 적게 다룸 |
| 시간적 맥락 | 결과가 변경되었을 수 있는 버전, 상태, 단계에 적용 |
| 빠뜨림 | 대화에서 말한 의도를 결과가 실어야 했는데 싣지 않음 |

## 사용 시기

**사용**:
- 산출물이 나온 뒤 — AI가 만들었든, 분석으로 얻었든, 이미 내린 결정이든, 이 세션에서든 다른 곳에서든 — 맥락에 대한 적용 가능성이 불확실할 때
- 요청한 것 가운데 빠진 게 없는지 알고 싶을 때
- 환경 가정이 대상과 맞지 않을 수 있을 때
- 관례 불일치가 의심될 때
- 출력 범위가 원래 요청을 초과할 수 있을 때

**건너뛰기**:
- 명시적 사양을 제공했고 결과가 정확히 따를 때
- 실행이 사소하거나 기계적일 때 (포맷팅, 오타 수정)
- 결과가 분명히 맥락에 잘 맞을 때

## 상태

**조건부** — AI 주도 활성화(Layer 2)는 AI 가 결과와 그것이 닿는 맥락 사이의 어긋남을 감지했을 때만 열리고, 열었다는 것을 말한다. `/contextualize`를 통한 사용자 호출은 항상 사용 가능하다.
