# Epharmoge — /contextualize (ἐφαρμογή)

그동안 말하고 정한 것 가운데 결과에 닿지 못한 것을 다시 본다 — 잘못 적용된 곳은 고쳐져 다시 읽히고, 내가 판단할 것은 제안과 함께 돌아온다 (ἐφαρμογή: 적용, 맞춤)

> [English](./README.md)

## Epharmoge란?

그리스어 ἐφαρμογή(적용/맞춤)의 현대적 재해석으로, **결과를 그것에 닿았어야 할 맥락에 다시 맞추는** 프로토콜이다. 그동안 말하고 정한 것을 되찾고, 결과가 닿는 모든 곳까지 따라가, 맥락이 이미 정해 둔 것은 고치고 사용자만 판단할 수 있는 것은 돌려준다. 결과는 이 세션의 산출물일 수도, 다른 곳에서 온 것 — 다른 세션의 작업, 문서, 계획 — 일 수도 있다.

### 핵심 문제

맥락은 대상에 온전히 닿지 못한다(`ApplicationDecontextualized`). 포커스가 이 일 저 일을 오가거나, 대화가 길어지거나, 일이 다른 손으로 넘어가는 동안 말하고 정한 것의 일부가 결과에서 떨어져 나간다 — 실리지 않은 결정, 읽히지 않은 규칙, 잊힌 목적, 결과와 맞지 않는 환경. 결과를 만든 AI 는 "끝냈다" 를 "맞다" 로 여기기 쉽고, 사용자는 자신이 한 말과 결과가 닿는 곳을 다 떠올리지 못한다 — 그래서 드리프트는 드러날 때까지 숨어 있다.

### 해결책

**되찾고, 고치고, 돌려준다**: AI 가 결과에 닿았어야 할 것 — 사용자의 말 · 결정 · 목적, 결과가 따라야 하는 규칙 — 을 되찾고, 결과가 닿는 모든 곳까지 따라가, 아무것도 바꾸지 않고 관측하며 닿지 못한 곳은 이름으로 남긴다. 그런 다음 둘을 가른다. 맥락이 이미 무엇이 맞는지 정해 두었는데 결과가 그와 다른 곳은 묻지 않고 고쳐 다시 읽고, 무엇이 그것을 정했는지 알린다. 시야에서 빠졌고 지금 무엇을 뜻하는지가 사용자의 판단인 것은 다시 펼쳐 보인다 — 어디서 한 말인지, 그것이 빠져서 사용자에게 무엇이 생기는지 — 구체적 행동들과 AI 가 택할 행동을 함께. 한 바퀴마다 한 장을 돌려주고 그 실행의 몫은 거기서 끝난다. 답은 요구되지 않고, 따로 "끝" 도 묻지 않는다. 사용자가 자기 말로든 "제안대로" 로든 답하면 다음 바퀴가 반영한다. 탈맥락화된 실행을 맥락화된 실행으로 변환한다.

### 다른 프로토콜과의 차이

| 프로토콜 | 주도자 | 타입 시그니처 |
|----------|--------|---------------|
| Aitesis | AI-guided | `ContextInsufficient → SufficientContext` |
| Merismos | User-initiated | `GoalPlanUncompiled → ConditionBearingUnitPlan` |
| **Epharmoge** | **AI-guided** | **`ApplicationDecontextualized → ContextualizedExecution`** |
| Katalepsis | User-initiated | `TargetUngrasped → VerifiedUnderstanding` |

### Aitesis와의 차이

| 관점 | Aitesis | Epharmoge |
|------|---------|-----------|
| 타이밍 | 결과가 있기 전 | 결과가 있은 뒤 |
| 방향 | AI가 스스로 모으고 사용자의 Unknown을 돌려줌 | AI가 결과에 닿았어야 할 것을 되찾아, 정해진 것은 고치고 사용자가 판단할 것은 돌려줌 |
| 축 | Context fitness | Context fitness |
| 결핍 | `ContextInsufficient` | `ApplicationDecontextualized` |
| 해소 | `SufficientContext` | `ContextualizedExecution` |

같은 축(context fitness), 반대 타이밍, 다른 대상 — 결과가 있기 전엔 AI에게 부족한 것, 뒤엔 결과에 닿지 못한 것. Aitesis는 "내가 스스로 닿을 수 있는 것은 무엇이고, 당신 몫은 무엇인가?"를 묻고, Epharmoge는 "이 결과 — 내 것이든 누구의 것이든 — 가 오는 길에 무엇을 잃었고, 닿는 곳에 맞는가?"를 묻는다. 둘 다 AI 가 정할 수 있는 것은 정하고 나머지는 사용자에게 돌려준다. 상호 보완적이지, 중복이 아니다.

## 프로토콜 흐름

```
한 바퀴 → 결과에 닿았어야 할 것을 되찾고, 결과가 닿는 모든 곳 관측, 정해진 것을 반영하며 고칠 때마다 다시 읽음 (비표시)
한 장   → 고친 것과 그것을 정한 근거; 사용자의 몫과 구체적 행동 · AI 가 택할 행동; 맞는 것; 닿지 못한 곳
돌려줌  → 한 장과 함께 그 실행의 몫이 끝난다 — 답은 요구되지 않고, 따로 "끝" 없음
답      → 답이 오면 다음 바퀴가 반영하고 새 한 장을 돌려준다
```

## 불일치 신호

| 신호 | 탐지 |
|------|------|
| 환경 가정 | 결과가 현재 맥락에서 검증되지 않은 환경 상태를 가정 |
| 관례 불일치 | 결과가 일반적 모범 사례를 따르지만 프로젝트에 로컬 관례가 존재 |
| 범위 초과 | 결과가 관찰된 사용 사례가 요구하는 것보다 많거나 적게 다룸 |
| 시간적 맥락 | 결과가 변경되었을 수 있는 버전, 상태, 단계에 적용 |
| 빠뜨림 | 대화에서 말한 의도를 결과가 실어야 했는데 싣지 않음 |
| 결정 드리프트 | 앞서 내린 결정 — 다른 일을 길게 하기 전에, 다른 세션에서, 리뷰에서 — 을 결과가 싣지 않음 |

## 사용 시기

**사용**:
- 세션이 길었거나 포커스가 여러 일을 오갔을 때, 결과가 오는 길에 무엇을 잃었는지 알고 싶을 때
- 다른 세션 · 에이전트 · 리뷰 · 머지를 거쳐 돌아온 작업에 내가 정한 것이 실렸는지 알고 싶을 때
- 요청한 것 가운데 빠진 게 없는지 알고 싶을 때
- 환경 가정이나 로컬 관례가 결과가 닿는 곳과 맞지 않을 수 있을 때

**건너뛰기**:
- 결과가 명시적 사양 하나만 따르고 그 밖에 한 말이 없을 때
- 실행이 사소하거나 기계적일 때 (포맷팅, 오타 수정)

## 상태

**조건부** — AI 주도 활성화(Layer 2)는 결과에 닿았어야 할 것이 닿지 않았거나 결과가 놓이는 곳에 맞지 않는다는 것을 AI 가 감지했을 때만 열리고, 열었다는 것을 말한다. `/contextualize`를 통한 사용자 호출은 항상 사용 가능하다.
