# /preview — Proplasma (πρόπλασμα)
<a name="proplasma--preview-πρόπλασμα"></a>

> [English](./README.md)

<a name="proplasma란"></a>
## 정의

Proplasma는 대리석에 조각하기 전에 먼저 빚어 보는 예비 점토 모형을 뜻하는 그리스어 πρόπλασμα에서 이름을 가져왔습니다. 방향을 확정하기 직전에 후보 방향들의 차이를 보여 주는 가벼운 임시 시제품(probe)을 만들어 지도 위에 나란히 놓아 줌으로써, 각 방향이 내 목적에 실제로 어떤 모습일지 눈으로 보고 결정하게 돕는 프로토콜입니다.

<a name="핵심-문제"></a>
## 문제

방향을 결정하기 직전에 후보가 둘 이상 잘 정리되어 있어도, 말로만 들어서는 각 방향을 택했을 때 어떤 모습이 될지 판단이 서지 않을 때가 있습니다. 결과를 눈으로 보고 고르는 대신 머릿속으로만 짐작해 보게 되어, 일반적인 원칙에 결정을 미루거나 고르는 대신 선택지를 다시 짜거나 "직접 봐야 알 것 같다"며 멈추게 됩니다.

## 결과

방향을 확정하면 AI는 임시 시제품을 폐기하며, 어떤 시제품을 지웠고 무엇을 더 정리해야 하는지 보고합니다. 최종적으로 선택한 방향, 그 결정을 가른 지도 칸들(직접 본 시제품, 설명뿐, 여러분의 말, 출처나 실제 관찰에서 온 증거 중 무엇에 기대는지 포함), 그리고 아직 열린 물음과 그것을 해결할 방법만 남습니다.

<a name="사용법"></a>
## 사용법

다음과 같이 입력합니다:

```
/preview [지금 확정하려는 방향 결정]
```

무엇이든 만들기 전에 AI는 후보가 둘 이상이고 임시 시제품(probe)으로 그 차이를 보여 줄 수 있는 상황인지 먼저 확인합니다(그렇지 않다면 이유와 함께 무엇으로 결정을 내릴 수 있을지 안내합니다). 이어서 여러분의 목적에 대해 파악한 바와 예시들 사이에서 무엇이 달라지고 어떤 세부 사항을 임시 값으로 채울지(목적에 비추어 후보들이 갈리는 축과 임시 시제품 정책)를 근거와 함께 먼저 알립니다. 그다음 그 축 위에서 서로 다른 선택을 보여주는 가벼운 임시 시제품 — 짧은 예시 글이나 격리된 임시 목업 — 을 만들어 방향 지도와 함께 보여 줍니다.

지도의 각 칸은 축마다 각 방향의 모습이 어떠한지, 그리고 그것이 무엇에 기대고 있는지(직접 본 시제품, 설명뿐, 여러분의 말, 또는 출처나 실제 관찰에서 온 증거)를 밝힙니다. 여러분이 예상했던 바를 시제품이 보여 준 모습 옆에 나란히 놓아 어디서 맞고 어디서 갈리는지도 드러냅니다. 번호 메뉴에 묶이지 않고 평소 말하듯 다음과 같이 진행할 수 있습니다:
- 이미 만든 시제품에 대해 묻거나, 초안 스펙을 고치거나, 시제품들을 조합하거나, 빠진 후보를 시제품으로 보여 달라고 요청합니다(AI가 스펙을 다시 알린 뒤 새로 만듭니다).
- 실제 코드나 자료를 바꾸지 않고 읽거나 실행해 확인해 달라고 요청합니다(그 결과는 시제품이 아니라 증거로 지도 칸에 들어갑니다).
- 언제든 멈출 수 있으며, 멈추면 방향을 정할 때까지 실행과 시제품이 그대로 유지됩니다.
- 시제품으로 본 방향이나 조합을 택하거나, 어떤 시제품도 보여 주지 않은 방향을 택해 닫습니다(이 경우 만들어 본 적 없는 미래라는 사실이 함께 기록됩니다).

### 배경과 해법

**Proplasma**는 그리스어 πρόπλασμα(대리석에 조각하기 전에 먼저 빚어 보는 예비 점토 모형)를 재해석한 프로토콜입니다. 말로만 봐서는 방향을 알아볼 수 없을 때(`DirectionUnrecognizable`), 선택지가 아무리 잘 정리되어 있어도 결과를 눈으로 알아보는 대신 머릿속으로만 시뮬레이션하게 됩니다.

**시뮬레이션이 아닌 대비(Contrast over Simulation)** 와 **근거를 보이고, 단정하지 않는다(Grounded, not asserted)**: AI는 목적이 걸린 발산 축(여러분이 말하기 전까지는 AI의 읽기로 표시)과 placeholder 정책을 초안으로 세워 생성 전에 근거와 함께 중계하고, 축 위에서 서로 다른 값을 가지는 probe들을 만듭니다. AI가 보기에 대비가 부족하면 근거와 함께 알리고 스펙을 다시 중계해 직접 펼치거나 제안하며, 이미 미래가 충분히 보인다고 읽으면 근거와 함께 닫기를 제안합니다. 실행을 닫는 것은 언제나 사용자입니다. probe는 명백한 합성물로 어떤 주장의 증거도 될 수 없으며, 결과를 수확한 뒤 각 probe의 처분 결과를 선언하며 폐기합니다(파기 실패 시 침묵하지 않고 정리 핸드오프와 함께 선언합니다).

### 다른 프로토콜과의 차이

| Protocol | Initiator | Type Signature |
|----------|-----------|---------------|
| Euporia | Hybrid | `AbstractAporia → ResolvedEndpoint` |
| Horismos | AI-guided | `BoundaryUndefined → DefinedBoundary` |
| **Proplasma** | **Hybrid** | **`DirectionUnrecognizable → DirectionalContrast`** |
| Analogia | AI-guided | `MappingUncertain → MappingAssessment` |
| Katalepsis | User-initiated | `TargetUngrasped → VerifiedUnderstanding` |

**삼분법**: 이해 부족 → `/grasp` (이해했는지 검증); 경계 부족 → `/bound` (어디까지인지 확정); **미래 인식 불가 → `/preview` (어느 방향인지 보고 판단)**.

**활성화하지 않을 때**: 설명만으로 미래가 이미 보일 때, 한 선택지의 뜻을 묻는 질문일 때, 각 방향의 모습이 아니라 이미 쓰이는 비유나 설명에서 추론이 성립하는지 따지는 선택일 때(`/ground`), 실제 증거로만 판단할 수 있는 결정일 때, 비교하기에 후보군이 너무 얇을 때.

### 파탄 조건 3종

프로토콜의 정당성은 스펙 중계 → probe 생성 → 지도 → 사용자의 닫음 → 폐기 검증으로 이어지는 사슬에 있습니다.

| 파탄 | 가드 |
|------|------|
| 근거와 함께 중계되기 전에 probe 값을 커밋한 발산 축 | 모든 생성 전에 스펙 중계가 먼저 나가며, 초안의 어떤 요소든 어느 라운드에서나 되돌릴 수 있음 |
| 영구 프로젝트 파일 쓰기 | 임시 격리 + 생성 시점 cleanup 등록 |
| probe의 증거 취급 | 수확과 모든 잔존물에서 probe는 어떤 주장의 증거도 아님; 증거는 실제로 읽거나 돌려 본 것에서만 옴 |

</details>
