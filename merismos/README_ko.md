# Merismos (μερισμός) — /apportion

> [English](./README.md)

자율 실행이 시작되기 전에, 목표를 굵은 실행 단위로 나누고 각 단위의 완료 조건을 도출합니다.

## 타입 시그니처

```
(GoalPlanUncompiled, User, APPORTION, AutonomousGoal × ExecutionHorizon) → ConditionBearingUnitPlan
```

## 기능

Merismos는 두 부분으로 이루어진 무상태 계획 컴파일러입니다. 목표의 의무(obligation)를 읽고, 인용할 수 있는 이음매 — 의존성 간선, 산출물 경계, 검증 지점, 소유권 전환 — 에서 굵은 단위로 자르며, 각 단위를 하나의 실행 지평(execution horizon)에 대고 판정합니다. 이어서 각 단위의 조건을 도출합니다: 완료 술어(그 단위가 결과를 냈는가)와 불변 술어(그 실행이 경계를 지켰는가). 주어가 특정 단위가 아니라 목표 전체인 조건은 단위마다 뿌리지 않고 계획 층위에 남깁니다. 각 단위는 증서 하나에 컴파일된 검사 · 미보장으로 수용된 공백 · 나중의 판단에 맡긴 유보를 모두 함께 싣습니다 — 그래서 통과한 검사가 아직 판단을 기다리는 done 을 대신하지 않습니다. 흐린 의무를 날카롭게 하면 검사가 될 수 있으면, 초안이 그 검사를 제안하고 사용자가 받습니다. 액션 실행 전 차단으로만 지킬 수 있는 의무는 범위 밖으로 선언되어 하니스 substrate에 위임됩니다.

실행은 사용자 없이 진행되므로, 한 장은 실행이 닿을 권한 — 종류 · 대상 · 한계마다 — 도 보여, 사용자가 떠나기 전에 정합니다; 받으면 한 장의 다른 줄과 같이 보인 그대로 채택됩니다. 계획 전체는 실행에 닿는 매 턴 한 장에 보이고, 사용자는 자기 말로 고치고 받습니다. 받으면 계획은 오래 남는 carrier 에 실리고, navigation block 이 그것을 가리키며, 계획은 자율 실행에 넘겨집니다 — Claude Code 에서는 `/goal` 같은 완료조건 실행기. 세션이 실행을 시작할 수 없으면 그 block 이 넘김이고, 사용자가 실행을 시작합니다.

방출되는 계획은 단위와 그 조건, 권한, 의심, 실행의 의무를 담습니다: 순서, 독립성, 조정, 종료 토폴로지는 여기서 정하지 않습니다.

**핵심 원칙**: 순서보다 분배 · 편의보다 커버리지 · 야망보다 적합 · 주장된 관절보다 선언된 이음매 · 넘김은 의무를 싣는다. Merismos의 어떤 것도 실행 구간으로 살아남지 않습니다.

## 활성화 시점

- 자율 실행이 의도된 목표에 대해 사용자가 `/apportion` 호출 (사용자 주도만 해당) — 단, 그 목표가 아직 각자 자기 완료 조건이 정해진 단위들로 담겨 있지 않을 때

## 두 개의 하드 불변식

| 불변식 | 무엇을 막는가 |
|--------|--------------|
| **커버리지** — 모든 목표 의무는 어떤 단위에 속하거나(그 단위에서 컴파일되거나, 미보장으로 수용되거나, 유보되거나), 범위 밖으로 명시 위임된다 | 방출된 검사가 전부 통과하는데 원래 의무 하나가 어느 단위에도 속하지 않는 상태 — 국소적으로 수렴하고 전역적으로 거짓말하는 계획 |
| **적합** — 모든 단위는 하나의 실행 지평에 맞거나, 사용자가 자기 말로 그 적합 판정을 넘어 받았다 | 단위가 자기를 집행해야 할 바로 그 구간을 넘쳐서, 단위 경계가 막으려던 거짓 완료와 컨텍스트 압축 실패를 재현하는 상태 |

이음매 품질은 **불변식이 아닙니다**. 각 절단은 자기가 놓인 이음매를 인용하거나 스스로를 휴리스틱이라 선언합니다 — 추상 목표에는 근거 있는 관절이 아예 없을 수 있고, 그런데도 있다고 주장하면 거짓 정밀도가 됩니다. 선언은 없는 관절을 인증하는 대신 판단을 보이게 만듭니다.

## 결합 규칙

한 단위 = 한 실행 구간 = 한 엔트리이며, 엔트리는 그 단위의 증서 전체를 싣습니다. 조건마다 엔트리를 내면 단위의 실행 정체성이 중복되고, 데카르트곱은 같은 일을 더 노골적으로 합니다. 술어 종류(`completion` / `invariant`)는 각 조건에 남겨서 출처가 읽히도록 합니다. 주어가 목표 전체인 조건 — 최종 통합, 전역 비회귀, 목표 전체 수용 — 은 계획 층위에 남아, 그 조건을 언제 발화해도 안전한지를 말하는 계획-상태 요구조건을 지닙니다: 이는 오직 계획 상태만의 속성이며, 특정 단위나 순서 위치를 지목하지 않습니다.

## 넘김

받은 계획은 언제 어디서 시작되든 그 실행이 따를 의무를 싣습니다 — 계약의 `handoffObligations`, `/conduct` 가 자기 substrate 에 싣는 것과 같은 넘김 의무입니다: 사용자에게 기대지 않는 일은 기다리지 않고 하고, 계획이 끝나면 모든 단위의 결과를 들고 한 번 돌아오며, 사용자에게 기대는 것 — 싣고 간 의심이 닿는 되돌릴 수 없는 단위가 그 가운데 있습니다 — 은 그 돌아옴에 그 때문에 진행되지 않은 것과 함께 실립니다; 사용자 대신 정하는 것은 없습니다. 단위를 먼저 배치하려는 사용자 — 예컨대 `/conduct` 로 — 는 받을 때 그렇게 말하고, 그러면 navigation block 이 나중에 시작하는 넘김이 됩니다.

## 합성

받은 계획은 세션 텍스트와 carrier 위의 navigation block 으로 나가므로, 뒤의 어떤 작업이든 — `/conduct` 로 설계한 방법, 트래커의 이슈, 다른 세션 — 포인터로 읽습니다. block 을 읽는 것은 계획을 접지할 뿐 아무것도 시작하지 않습니다. 구체적인 실행자 선택은 밖에 있습니다: 단위는 능력 요구사항을 담을 뿐 결속을 담지 않습니다. 구간 이후에는 `/contextualize`와 `/grasp`가 검증합니다.

## 알려진 제한 사항

- **검증되지 않은 플랫폼 주장**: 세션이 받는 턴에 `/goal` 을 시작할 수 있다는 것은 어느 Claude Code 버전에서도 검증되지 않았음; 시작할 수 없으면 navigation block 이 넘김이고 사용자가 실행을 시작함.
- **의무 읽기는 휴리스틱**: 발화되지 않았고 상위에서 포착되지 않은 의무는 읽히지 않으므로, 커버리지는 *읽힌 것*에 대해서만 하드합니다. 한 장은 누락이 보이는 자리입니다: 의무는 실행에 닿는 매 턴 다시 읽히므로, 빠진 의무를 말하면 계획에 들어옵니다.
- **이음매 근거는 자주 부재**: 추상 목표는 근거 있는 관절을 제공하지 않는 일이 잦고, 휴리스틱 절단은 중복 셋업이나 단위 간 상태 누출을 남길 수 있습니다.
- **지평 적합은 추정**: 실행 전에 목표 서술만 보고 판정합니다; override 경로가 있는 이유는 사용자가 추정보다 잘 아는 경우가 많기 때문입니다.
- **술어 커버리지**: 주관적 품질 기준은 도출되지 않습니다. 날카롭게 하면 술어가 될 수 있는 것은 초안이 그 검사를 그 의무의 검사로 제안하고, 사용자가 물릴 때만 공백으로 남습니다. 검사가 아니라 판단이 정하는 것은 유보됩니다. 실행이 스스로 바꿔 통과시킬 수 있는 검사는 한 장에 그렇다고 표시됩니다.
- **넘김의 이행은 실행의 몫**: 계획을 넘기면 이 프로토콜은 끝났습니다; 실행이 넘김의 의무를 지키는지는 실행의 몫이고, 사전 차단은 하니스 substrate 의 몫입니다.
