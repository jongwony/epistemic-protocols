# Merismos (μερισμός) — /apportion

> [English](./README.md)

자율 실행이 시작되기 전에, 목표를 굵은 실행 단위로 나누고 각 단위의 완료 조건을 도출합니다.

## 타입 시그니처

```
(GoalPlanUncompiled, User, APPORTION, AutonomousGoal × ExecutionHorizon) → ConditionBearingUnitPlan
```

## 기능

Merismos는 두 부분으로 이루어진 무상태 계획 컴파일러입니다. 목표의 의무(obligation)를 읽고, 인용할 수 있는 이음매 — 의존성 간선, 산출물 경계, 검증 지점, 소유권 전환 — 에서 굵은 단위로 자르며, 각 단위를 하나의 실행 지평(execution horizon)에 대고 판정합니다. 이어서 각 단위의 조건을 도출합니다: 완료 술어(그 단위가 결과를 냈는가)와 불변 술어(그 실행이 경계를 지켰는가). 주어가 특정 단위가 아니라 목표 전체인 조건은 단위마다 뿌리지 않고 계획 층위에 남깁니다. 방출은 단위당 goal 엔트리 하나이며, 각 엔트리는 그 단위의 해결 증서를 싣습니다 — 완료 조건이 도출된 단위는 조건들을 하나의 leaf 술어로 논리곱하고, 도출되지 않은 단위는 승인된 완료 증인과 컴파일된 불변 논리곱항을 싣습니다. 하위 완료조건 enforcer(Claude Code에서는 `/goal`)가 이를 소비합니다. 액션 실행 전 차단으로만 지킬 수 있는 의무는 범위 밖으로 선언되어 하니스 substrate에 위임됩니다.

방출되는 계획은 의도적으로 **지휘 이전(pre-conduct)** 입니다: 단위 경계와 조건만 담습니다. 순서, 독립성, 조정, 종료 토폴로지, 라우팅은 `/conduct`의 몫으로 남습니다.

**핵심 원칙**: 순서보다 분배 · 편의보다 커버리지 · 야망보다 적합 · 주장된 관절보다 선언된 이음매. Merismos의 어떤 것도 실행 구간으로 살아남지 않습니다.

## 활성화 시점

- 자율 실행이 의도된 목표에 대해 사용자가 `/apportion` 호출 (사용자 주도만 해당) — 단, 그 목표가 아직 각자 자기 완료 조건이 정해진 단위들로 담겨 있지 않을 때

## 두 개의 하드 불변식

| 불변식 | 무엇을 막는가 |
|--------|--------------|
| **커버리지** — 모든 목표 의무는 어떤 단위에 속하거나, 범위 밖으로 명시 위임되거나, 미보장으로 기록상 수용된다 | 방출된 leaf가 전부 통과하는데 원래 의무 하나가 어느 단위에도 속하지 않는 상태 — 국소적으로 수렴하고 전역적으로 거짓말하는 계획 |
| **적합** — 모든 단위는 하나의 실행 지평에 맞거나, 사용자가 기록한 override를 지닌다 | 단위가 자기를 집행해야 할 바로 그 구간을 넘쳐서, 단위 경계가 막으려던 거짓 완료와 컨텍스트 압축 실패를 재현하는 상태 |

이음매 품질은 **불변식이 아닙니다**. 각 절단은 자기가 놓인 이음매를 인용하거나 스스로를 휴리스틱이라 선언합니다 — 추상 목표에는 근거 있는 관절이 아예 없을 수 있고, 그런데도 있다고 주장하면 거짓 정밀도가 됩니다. 선언은 없는 관절을 인증하는 대신 판단을 보이게 만듭니다.

## 결합 규칙

한 단위 = 한 실행 구간 = 한 엔트리이며, 그 단위의 조건들은 하나의 leaf 술어로 논리곱됩니다. 조건마다 엔트리를 내면 단위의 실행 정체성이 중복되고, 데카르트곱은 같은 일을 더 노골적으로 합니다. 술어 종류(`completion` / `invariant`)는 각 논리곱 항에 남겨서, 집행이 이들을 합치더라도 출처는 읽히도록 합니다. 주어가 목표 전체인 조건 — 최종 통합, 전역 비회귀, 목표 전체 수용 — 은 계획 층위에 남아, 그 조건을 언제 발화해도 안전한지를 말하는 계획-상태 요구조건을 지닙니다: 이는 오직 계획 상태만의 속성이며, 특정 단위나 순서 위치를 지목하지 않습니다 — 순서를 지목하는 일은 이 프로토콜이 아니라 `/conduct`의 축이기 때문입니다.

## 합성

상위의 `/bound`는 양쪽을 좁힙니다: 어떤 이음매가 절단 후보인지, 그리고 단위들이 어떤 조건에 종속되는지. `/conduct`와의 관계는 양방향이며 가드가 걸려 있습니다 — 단위 배열이 자명하지 않을 때 다단위 계획이 `/conduct`로 흐르고, 반대로 미해결 자율 구역에 도달한 `/conduct` 활성화가 그 구역을 되돌려 보냅니다. 두 간선 모두 advisory이고 재진입 금지 가드를 지녀서 쌍이 재귀하지 않습니다: 지휘된 계획의 단위 술어는 conduct의 goal-met 구역에 대해 명시된 종료 근거가 되어 되돌아오지 않고 — 라운드 수나 dry ceiling으로 멈추는 구역은 대신 커버리지 한계를 지닙니다 —, 이미 지휘된 구역의 토폴로지는 이 프로토콜이 다시 지휘하지 않는 고정 입력입니다. 단일 단위는 `/conduct`를 아예 건너뛰고, 단위 집합은 순서만이 아니라 다섯 축 — 순서, 독립성, 재조정, 종료, 라우팅 — 전부에서 지휘가 자명할 때 건너뜁니다.

`/apportion`은 `/goal`을 호출하지 않습니다 — 방출이 인식론적 종료점이며, 자율 구간 시작은 사용자의 별도 행위입니다. 구체적인 실행자 선택도 밖에 있습니다: 단위는 능력 요구사항을 담을 뿐 결속을 담지 않습니다. 구간 이후에는 `/contextualize`와 `/grasp`가 검증합니다.

## 알려진 제한 사항

- **Bounded 플랫폼 주장**: `/goal` leaf-executor 특성은 Claude Code v2.1.140 기준으로만 검증됨; 하니스 버전 변경 시 재검증 필요.
- **의무 읽기는 휴리스틱**: 발화되지 않았고 상위에서 포착되지 않은 의무는 읽히지 않으므로, 커버리지는 *읽힌 것*에 대해서만 하드합니다; 확인 게이트가 교정 지점입니다.
- **이음매 근거는 자주 부재**: 추상 목표는 근거 있는 관절을 제공하지 않는 일이 잦고, 휴리스틱 절단은 중복 셋업이나 단위 간 상태 누출을 남길 수 있습니다.
- **지평 적합은 추정**: 실행 전에 목표 서술만 보고 판정합니다; override 경로가 있는 이유는 사용자가 추정보다 잘 아는 경우가 많기 때문입니다.
- **술어 커버리지**: 주관적 품질 기준은 도출되지 않습니다; prose 조건이 아니라 residual로 표면화됩니다.
- **실행 중 보호 없음**: 컴파일 타임 전용 — 사전 차단 위험은 전적으로 하니스 substrate의 책임입니다.
