# /apportion — Merismos (μερισμός)
<a name="merismos-μερισμός--apportion"></a>

> [English](./README.md)

## 정의

Merismos는 부분으로 나눔이나 배분을 뜻하는 그리스어 μερισμός에서 이름을 가져왔습니다. 자율 실행을 시작하기 전에 하나의 목표를 실행 단위로 나누고, 단위마다 완료 확인 조건과 감수할 빈틈, 여러분의 판단으로 남겨 둘 항목, 그리고 자율 실행이 사용할 권한을 한 장의 계획 시트로 정리해 주는 프로토콜입니다.

<a name="활성화-시점"></a>
## 문제

목표를 단위로 나누지 않은 채 곧바로 자율 실행에 맡기면 작업 하나가 한 번의 실행 구간을 넘치거나, 일부 확인만 통과한 채 여러분의 판단이 필요한 부분이 완료로 처리되거나, 원래 요구사항이 빠진 채 진행되기 쉽습니다. 목표를 자율 실행에 맡기려는데 어떤 단위로 나누어 실행할지, 각 단위가 언제 끝나는지 아직 계획이 없을 때 `/apportion`을 쓰세요.

## 결과

계획을 확정하면 시트에 표시된 권한이 함께 승인되며, 영구 저장 위치와 이를 가리키는 블록으로 기록되어 자율 실행(Claude Code의 `/goal` 등, 혹은 `/conduct`로 단위를 먼저 배치하거나 직접 실행을 시작할 때는 해당 블록)으로 넘어갑니다. 실행 전에 정해야 할 사항과 권한은 미리 확정되고, 계획에는 여러분의 판단이 필요 없는 작업을 기다리지 않고 진행한 뒤 모든 단위의 결과와 보류된 판단 항목을 마지막에 한 번에 돌려주라는 실행기의 의무가 함께 전달됩니다.

## 설치

```
claude plugin marketplace add https://github.com/jongwony/epistemic-protocols
claude plugin install merismos@epistemic-protocols
```

<a name="사용법"></a>
## 사용법

다음과 같이 입력합니다:

```
/apportion [목표]    # 목표를 단위로 나누고 각 단위의 완료 조건을 도출
```

AI가 목표에서 해야 할 일들을 읽고 한 번의 자율 실행 구간에 맞을 것으로 추정되는 단위들로 나눈 뒤(이 적합 판정은 직접 말로 덮어쓸 수 있습니다), 계획 전체를 한 장의 시트로 보여 줍니다. 시트에는 단위마다 완료 여부와 경계 유지 여부를 확인하는 조건, 모호한 요구사항을 구체화해 제안한 확인 조건, 확인 없이 감수하기로 한 빈틈, 그리고 여러분의 판단으로 남겨 둔 항목이 함께 적힙니다. 목표 전체에 걸친 조건은 계획 수준에 따로 놓이며, 여러분 없이 실행이 돌아가는 동안 사용할 권한(종류·대상·한계)과 AI의 의심도 시트에 함께 표시됩니다.

시트를 보며 매 턴 자신의 말로 고치고, 마음에 들면 계획을 확정해 받습니다.

### 이름과 타입 시그니처

**Merismos** (μερισμός: 부분으로 나눔):

```
(GoalPlanUncompiled, User, APPORTION, AutonomousGoal × ExecutionHorizon) → ConditionBearingUnitPlan
```

### 기능

Merismos는 두 단계로 작동하는 무상태 계획 컴파일러입니다:
1. 목표의 의무(obligation)를 읽고 인용 가능한 이음매(의존성 간선, 산출물 경계, 검증 지점, 소유권 전환)에서 굵은 단위로 자르며, 각 단위를 하나의 실행 지평(execution horizon)에 비춰 판정합니다.
2. 각 단위의 완료 술어(결과 달성 여부)와 불변 술어(경계 유지 여부)를 도출하고, 목표 전체가 주어인 조건은 계획 층위에 남깁니다.

각 단위는 증서 하나에 컴파일된 검사, 미보장으로 수용된 공백, 나중 판단으로 미룬 유보를 함께 실어, 통과한 검사가 아직 판단을 기다리는 완료를 대신하지 않게 합니다. 실행 전 차단으로만 지킬 수 있는 의무는 범위 밖으로 선언해 하니스 substrate에 위임합니다. 방출되는 계획은 단위와 조건, 권한, 의심, 실행의 의무만 담으며 순서, 독립성, 조정, 종료 토폴로지는 정하지 않습니다.

**핵심 원칙**: 순서보다 분배 · 편의보다 커버리지 · 야망보다 적합 · 주장된 관절보다 선언된 이음매 · 넘김은 의무를 싣는다. Merismos의 어떤 것도 실행 구간으로 살아남지 않습니다.

### 두 개의 하드 불변식

| 불변식 | 무엇을 막는가 |
|--------|--------------|
| **커버리지** — 모든 목표 의무는 어떤 단위에 속하거나(컴파일·미보장 수용·유보), 범위 밖으로 명시 위임됨 | 방출된 검사는 모두 통과하는데 원래 의무 하나가 어느 단위에도 속하지 않는 상태(국소적 수렴과 전역적 거짓말) |
| **적합** — 모든 단위는 하나의 실행 지평에 맞거나, 사용자가 자기 말로 그 판정을 넘어 받음 | 단위가 실행 구간을 넘쳐 거짓 완료와 컨텍스트 압축 실패를 재현하는 상태 |

이음매 품질은 **불변식이 아닙니다**. 각 절단은 근거가 되는 이음매를 인용하거나 휴리스틱이라 선언해, 없는 관절을 꾸며내는 대신 판단을 드러냅니다.

### 결합 규칙, 넘김, 합성

- **결합 규칙**: 한 단위는 한 실행 구간이자 그 단위의 증서 전체를 싣는 한 엔트리이며, 각 조건에 술어 종류(`completion` / `invariant`)를 남깁니다. 목표 전체 조건(최종 통합, 전역 비회귀, 목표 전체 수용)은 계획 층위에 남아 언제 발화해도 안전한지 나타내는 계획-상태 요구조건을 지닙니다. 이는 특정 단위나 순서 위치를 지목하지 않는, 오직 계획 상태만의 속성입니다.
- **넘김 (`handoffObligations`)**: 확정된 계획은 모든 실행에 의무를 넘깁니다. 사용자에게 기대지 않는 일은 기다리지 않고 실행하며, 계획이 끝나면 모든 단위의 결과를 들고 한 번 돌아옵니다. 싣고 간 의심이나 실행 중 찾은 증거가 걸린 되돌릴 수 없는 단계는 대신 결정하지 않고 그 때문에 진행되지 않은 작업과 함께 돌려줍니다.
- **합성**: 확정된 계획은 세션 텍스트와 carrier 위의 navigation block으로 남으므로 이후 작업(`/conduct`, 이슈 트래커, 다른 세션)에서 포인터로 읽을 수 있습니다. 단위는 능력 요구사항만 담고 특정 실행자에 묶이지 않습니다.

### 알려진 제한 사항

- **검증되지 않은 플랫폼 주장**: 계획을 받는 턴에 곧바로 `/goal`을 시작할 수 있는지는 Claude Code 버전에서 검증되지 않았습니다. 시작할 수 없으면 navigation block이 넘김이 되며 사용자가 실행을 시작합니다.
- **의무 읽기는 휴리스틱**: 직접 말하지도 않았고 앞선 작업에도 기록되지 않은 요구사항은 읽히지 않습니다. 실행에 닿는 매 턴 의무를 다시 읽으므로 빠진 의무를 시트에서 말하면 추가됩니다.
- **이음매 근거 부재**: 추상적인 목표는 근거 있는 관절이 없는 경우가 많으며, 휴리스틱 절단은 중복 셋업이나 단위 간 상태 누출을 남길 수 있습니다.
- **지평 적합은 추정**: 실행 전 목표 서술만 보고 판정하므로, 사용자가 자기 말로 적합 판정을 넘어 받을 수 있는 경로를 둡니다.
- **술어 커버리지**: 주관적 품질 기준은 검사로 도출되지 않습니다. 구체화해 검사가 될 수 있는 의무는 초안에서 검사로 제안하고 사용자가 그 제안을 거절할 때만 공백으로 남으며, 검사가 아니라 판단이 정하는 항목은 유보됩니다. 실행이 스스로 바꿔 통과시킬 수 있는 검사는 시트에 표시됩니다.
- **넘김의 이행은 실행의 몫**: 계획을 넘기면 프로토콜은 끝나며, 넘김 의무를 지키는 것은 실행의 몫이고 사전 차단은 하니스 substrate의 몫입니다.
