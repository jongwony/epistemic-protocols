<sub>`/elicit`을 쓰는 장면 (누르면 영상). 영상 속 값은 각색한 예시이며 실행 결과가 아닙니다.</sub>

<a name="호출-시점"></a>
## 언제 쓰나요

요청에 방향은 담겨 있지만 어떤 결과를 원하는지 아직 분명하지 않을 때 `/elicit`을 씁니다. AI가 먼저 `/elicit`을 제안할 때는 받아들이거나 거절할 수 있습니다. AI가 임의로 빈칸을 채워 진행하는 대신 여러분의 말과 코드베이스·규칙·과거 세션, 그리고 해당 영역의 결정 구조를 살펴 결과를 좌우할 결정 지점들을 끌어올립니다.

## 시작하는 법

요청과 함께 `/elicit`을 입력합니다.

첫 응답에서 AI는 지금까지 이해한 의도를 출처와 함께 읽어 주고, 아직 열려 있는 결정 지점들과 각 항목을 정하지 않고 두면 무엇이 달라지는지를 함께 보여 줍니다. AI가 스스로 판단해 먼저 열었을 때는 첫 응답이 제안으로 제시되며, 여러분이 받아들이거나 거절합니다. 자기 말로 답하거나, 제시된 선택지를 고르거나, 목록에 없는 새 기준을 추가하거나, 맞지 않는 기준을 빼 버릴 수 있고, 첫 화면을 보고 바로 "이 정도면 내 뜻에 맞다"고 마쳐도 됩니다.

AI는 스스로 밝힌 판단에 따라 되돌릴 수 있는 범위의 작업을 한 걸음 먼저 진행해 볼 수도 있으며, 이때는 여러분의 말을 어떻게 읽었고 어떤 근거로 어디까지 진행했는지 함께 설명합니다. 되돌릴 수 없는 작업은 언제나 승인을 기다립니다.

<a name="개요"></a>
## 끝나면 무엇이 남나요

매 라운드는 답을 강요하지 않고 지금까지 정리된 의도를 돌려줍니다:

- **내 말과 AI 제안의 구분** — 기록된 각 항목에는 여러분의 말에서 왔는지 AI의 제안인지가 표시됩니다. 여러분이 한 번 정한 값은 직접 말을 바꾸기 전까지 유지되며, AI의 제안은 제안으로 먼저 표시된 뒤 여러분이 받아들였을 때만 채택으로 기록됩니다.
- **열어 둔 항목의 유지** — 모든 질문에 답할 필요는 없습니다. 정하지 않고 남겨 둔 항목은 임의의 기본값으로 닫히지 않고 열린 상태 그대로 다음 작업에 전달됩니다.

뜻에 맞는지는 직접 정합니다. 그 전에도 언제든 멈추거나 다른 일로 넘어갈 수 있습니다. 마지막으로 정리된 의도가 그대로 남습니다.

<a name="이름"></a>
### 이름

그리스어 εὐπορία — 문자 그대로 "좋은 통로"(εὖ "잘" + πόρος "길") — 는 aporia(ἀπορία, "통로 없음")에서 해소를 향해 나오는 자원성을 가리킵니다. 플라톤 후기 변증법은 aporia와 euporia를 탐구의 짝지어진 계기로 엮으며, 이 프로토콜은 그 해소-통로 구조를 빌려왔습니다.

<a name="type"></a>
### Type

```
(AbstractAporia, Hybrid, REVERSE-INDUCE-CYCLE, IntentSeed)
  → ResolvedEndpoint
```

Lean 계약이 증명하는 것은 사용자의 말이 없는 턴이 기록된 값의 출처가 되지 않는다는 점입니다.

### 다른 프로토콜과의 관계

Euporia는 Periagoge(`/induce`)와 방향상 짝을 이룹니다. Periagoge는 구체적인 사례들에서 출발해 공통 개념으로 올라가고(상향), Euporia는 의도에서 출발해 그 의도가 갈리는 결정 좌표로 내려갑니다(하향). 두 프로토콜은 같은 변증법의 직교 방향으로 합쳐집니다(비형식적 방향 직교성이며 정식 범주론적 limit/colimit 쌍대성은 아닙니다).

축이 이미 정해진 의도는 해당 축을 다루는 프로토콜이, 여러 사례가 공유하는 개념을 새로 잡거나 다시 짚는 경우에는 Periagoge(`/induce`)가 더 잘 맞을 수 있습니다.
