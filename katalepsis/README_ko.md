# /grasp — Katalepsis (κατάληψις)
<a name="katalepsis--grasp-κατάληψις"></a>

> [English](./README.md)

<a name="katalepsis란"></a>
## 정의

Katalepsis는 확고한 파악이나 확실한 이해를 뜻하는 그리스어 κατάληψις에서 이름을 가져왔습니다. 누가 만들었든 눈앞에 있는 코드, 문서, 결과물을 여러분의 목적에 맞춘 지도 위에서 실제 자료와 대조하며 따라가고, 검증된 이해에 이르도록 돕는 프로토콜입니다.

<a name="핵심-문제"></a>
<a name="사용-시점"></a>
## 문제

규모가 큰 변경, 다른 사람이 작성한 코드, 밀도 높은 문서, 혹은 대신 만들어 준 결과물이 복잡할 때는 어디서부터 봐야 할지 막막하거나 확신 없이 고개만 끄덕이고 넘어가기 쉽습니다. 내용을 아직 따라가기 어렵거나 내가 이해한 바를 확인하고 싶을 때 `/grasp`를 쓰세요. 포매팅만 바뀐 사소한 결과이거나, 이미 내용을 이해했거나, 설명이 필요하지 않을 때는 건너뛰면 됩니다.

## 결과

프로토콜이 닫히면 목적을 중심으로 정리된 이해 지도가 남습니다. 지도에는 대상이 하는 일과 그 근거, 여러분이 직접 설명한 내용, 받아들인 AI의 설명이 각각 구분되어 기록되며, 아직 남은 확인과 그 방법, AI의 이견도 함께 남습니다.

## 설치

```
claude plugin marketplace add https://github.com/jongwony/epistemic-protocols

```

<a name="사용법"></a>
## 사용법

다음과 같이 입력합니다:

```
/grasp
```

또는 평소 말하듯 "뭘 했어?", "설명해줘", "이해하고 싶어", "이게 이해가 안 돼", "못 따라가겠어"라고 물어도 됩니다.

AI가 대상과 주변 출처를 먼저 읽은 뒤, 여러분의 목적(직접 말한 목적, 또는 한 줄로 바로잡을 수 있도록 AI가 파악한 목적으로 표시한 것)을 중심으로 이해 지도를 보여 줍니다. 지도는 목적이 걸린 측면마다 한 줄 핵심, 근거가 되는 사실과 자료, 그리고 여러분이 말한 자신의 해석을 대상이 실제로 하는 일과 구분해 나란히 놓습니다. AI는 각 측면을 가장 잘 전달하는 그림, 예시, 은유 하나로 설명하고, 요청하면 더 깊이 들어갑니다. 여러분은 자신의 말로 지도를 움직입니다:
- "알겠다"고 하면 그 측면은 AI의 설명을 받아들인 것으로 남습니다.
- "봐야 알겠다"고 하면 확인을 실행해 그 결과를 함께 봅니다.
- "이상하다"고 하면 그 해석을 확인할 수 있는 근거를 옆에 놓아 보고, 닿는 사실이 없으면 무엇으로 가릴 수 있을지 짚습니다.

지금 이해한 내용이 목적에 충분하다고 말하면 프로토콜이 닫힙니다.

### 배경과 해결책

**Katalepsis**는 스토아 철학의 κατάληψις(확고한 파악, 확실한 이해)를 재해석한 프로토콜로, 누가 만들었든 맥락에 있는 대상을 따라가며 검증된 이해에 이르게 돕습니다. 대상이 복잡하면 온전히 파악하지 못한 채(`TargetUngrasped`) 이해했다고 착각하거나 어디서 시작할지 몰라 막막해지기 쉽습니다.

**근거를 보이고, 단정하지 않는다 (Grounded, not asserted)**: 설명을 들었다고 해서 이해한 것으로 치지 않습니다. 각 측면은 대상이 거기서 하는 일(기대는 근거·결과 포함)과 여러분이 말한 것(자신의 읽기, AI 설명 수용, 또는 아직 없음)을 따로 둡니다.

### 단순 설명과의 차이

| 차원 | 단순 설명 | Katalepsis |
|------|----------|------------|
| 방향 | AI가 말하고, 사용자가 듣는다 | AI가 지도를 보이고, 사용자가 받아들이거나 보자고 하거나 반박하며 움직인다 |
| 진입점 | AI가 무엇을 설명할지 결정 | 사용자가 말한 목적, 또는 AI의 것으로 표시해 한 줄로 바로잡는 AI의 읽기 |
| 확인 | 설명 후 가정됨 | 측면마다 대상이 하는 일(근거 포함)과 사용자가 이해한 것(자신의 말 또는 받아들인 AI 설명)을 분리 |
| 끝 | 정의되지 않음 | 지금의 이해가 목적에 맞다고 말할 때 닫히며, 남은 확인·방법·AI 이견이 담긴 지도가 기록이 됨 |

### 프로토콜 흐름

```
수집   → 대상의 근거와, 그것에 닿는 출처를 읽음
지도   → 목적(사용자의 말, 또는 AI의 것으로 표시한 AI의 읽기)과 그 목적이 걸린
         측면들, 각각의 사실과 사용자 자신의 읽기
설명   → 측면마다 맞는 표현 하나로; 사용자가 청하거나 AI가 밝힌 판단으로
         돌린 확인은 사실 하나를 더함; 사용자의 읽기 곁에는 닿는 사실을
         놓음 — 닿는 사실이 없으면 무엇이 가릴지 말함
닫기   → 사용자가 지금의 이해가 목적에 맞다고 말함; 그때의 지도가
         이견과 함께 기록이 됨
```

### 지도가 싣는 것

| 측면 | 설명 |
|------|------|
| **목적이 걸린 것** | 목적에 필요한, 대상이 하는 일 — 표현 하나로 설명하고 요청 시 더 깊이 들어가며, 여러분의 읽기 곁에는 닿는 사실을 놓음 |
| **말하지 않은 가장자리** | 아직 말하지 않았지만 목적에 필요한 대상의 가장자리 — 대상의 근거에 기대어 지도에 드러냄 |
| **Contradiction** | 같은 범위에서 함께 성립할 수 없는 출처 있는 두 진술: 여러분이 한쪽을 쥔 모순은 한 라운드에 풀이(여러분의 말, 대상의 근거, 갈리는 까닭, 맞는 곳)까지 보이고, 대상 안의 모순은 발견으로 보이며, 앞선 AI 설명과의 모순은 AI가 바로잡음 |
| **확인** | 한 측면을 믿기 전에 보거나 해 볼 것 — 요청에 따라 돌려 결과를 측면 곁에 보임. 목적이 걸린 측면(여러분의 읽기가 말하는 일 포함)을 보일 확인이 AI에 닿으면 가장 싼 것을 판단을 밝혀 보고 전에 돌리고, 아니면 필요한 것과 함께 제안함. 결과는 대상에 대한 사실일 뿐 무엇을 이해했는지는 여러분 자신의 말로만 정해짐 |

</details>
