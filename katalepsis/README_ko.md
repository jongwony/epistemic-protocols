# Katalepsis — /grasp (κατάληψις)

맥락에 올라온 대상 — 코드, 문서, 결과물 — 에 대한 확실한 이해 달성 (κατάληψις: 확고하게 파악함)

> [English](./README.md)

## Katalepsis란?

스토아 철학의 κατάληψις (확고한 파악, 확실한 이해)를 현대적으로 재해석한 프로토콜 — 누가 만들었든 **맥락에 있는 대상을 사용자가 따라가며 검증된 이해에 도달**할 수 있게 합니다.

### 핵심 문제

대상이 복잡할 때 — 큰 변경, 남이 쓴 코드, 밀도 높은 논문 — 사용자는 종종 그것을 온전히 파악하지 못합니다 (`TargetUngrasped`). 이해했다고 생각하거나, 어디서부터 시작해야 할지 몰라 압도당할 수 있습니다.

### 해결책

**설명보다 이해**: 일방적으로 설명하거나 사용자를 시험하는 대신, AI가 먼저 대상과 그 주변 출처를 읽고 사용자의 목적 위에 이해의 지도를 보입니다 — 사용자가 말한 목적, 또는 AI의 것으로 표시한 AI의 읽기, 그리고 그 목적이 걸린 측면들을 한 줄의 핵심, 그것이 기대는 근거, 지금의 상태와 함께. AI는 한 번에 한 측면을 그것을 가장 잘 싣는 그림 · 예시 · 은유 하나로 설명하고, 사용자가 당길 때 더 깊이 들어갑니다. 지도는 사용자의 말로 움직입니다: "알겠다"는 그 측면을 AI의 설명에 기댄 채 받아들인 것으로 두고, "봐야 알겠다"는 확인을 돌려 결과를 함께 보며, "이상하다"는 그것을 가리는 근거와 만나거나, 근거가 없으면 판정 없이 무엇이 가릴지를 말합니다.

### 단순 설명과의 차이

| 차원 | 단순 설명 | Katalepsis |
|------|----------|------------|
| 방향 | AI가 말하고, 사용자가 듣는다 | AI가 지도를 보이고, 사용자가 그것을 움직인다 — 받아들이거나, 보자고 하거나, 반박하며 |
| 진입점 | AI가 무엇을 설명할지 결정 | 사용자가 말한 목적, 또는 AI의 것으로 표시한 AI의 읽기 — 한 줄로 바로잡힘 |
| 확인 | 설명 후 가정됨 | 측면마다 무엇에 기대는지 보임: 대상에 비춰 확인된 사용자 자신의 읽기, 함께 본 결과, 또는 AI의 설명뿐 |
| 끝 | 정의되지 않음 | 사용자가 목적에 충분히 이해했다고 말함 — 그때의 지도가 아직 확인할 것과 그 방법, AI의 이견과 함께 기록이 됨 |

## 프로토콜 흐름

```
수집   → 대상의 근거와, 그것에 닿는 출처를 읽음
지도   → 목적(사용자의 말, 또는 AI의 것으로 표시한 AI의 읽기)과 그 목적이 걸린
         측면들, 각각 무엇에 기대는지와 지금의 상태
설명   → 한 번에 한 측면, 맞는 표현 하나로; 사용자의 말에는 근거를 붙여 답함 —
         사용자가 청한 확인은 돌려 결과를 보이고, 근거 없이는 판정하지 않고
         무엇이 가릴지 말함 (gate interaction)
닫기   → 사용자가 충분히 이해했다고 말함; 그때의 지도가 이견과 함께 기록이 됨
```

## 사용 시점

**사용**:
- 상당한 코드 변경이 들어온 뒤 — 누가 한 것이든
- 사용자가 "뭘 했어?", "설명해줘", "이해하고 싶어", "이게 이해가 안 돼", "못 따라가겠어"라고 할 때
- 복잡한 리팩토링, 새 기능, 아키텍처 변경

**건너뛰기**:
- 사소한 변경 (오타, 포매팅)
- 사용자가 이미 이해를 보여줌
- 사용자가 명시적으로 설명을 거부

## 사용법

```
/grasp
```

## 지도가 싣는 것

| 측면 | 설명 |
|------|------|
| **목적이 걸린 것** | 사용자의 목적에 필요한, 대상이 하는 일 — 표현 하나로 설명하고 청하면 더 깊이; 사용자 자신의 읽기는 그것을 가리는 근거에 비춰 확인 |
| **말하지 않은 가장자리** | 사용자가 말하지 않았지만 목적에 필요한, 대상이 하는 일의 가장자리 — 대상의 근거에 기대야 하며, 다른 측면처럼 지도에 드러내 놓음 |
| **Contradiction** | 같은 범위에서 함께 성립할 수 없는 출처 있는 두 진술 — 누구의 것인지에 따라 다룸: 사용자가 한쪽을 쥔 모순은 한 라운드에 풀이까지 보이고(사용자의 말, 대상의 근거, 갈리는 까닭, 맞게 본 부분), 대상 안의 모순은 대상에 대한 발견으로 보이고, 앞선 AI 설명과의 모순은 AI 가 바로잡음 |
| **확인** | 사용자가 한 측면을 믿기 전에 보거나 해 보고 싶은 것 — 사용자의 말로 돌리고 결과를 측면 곁에 보임; AI는 사용자가 곧 내릴 판단이 AI의 설명에만 기댈 때에만 가장 싼 확인을 제안 |
