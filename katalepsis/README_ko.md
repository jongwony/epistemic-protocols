# Katalepsis — /grasp (κατάληψις)

맥락에 올라온 대상 — 코드, 문서, 결과물 — 에 대한 확실한 이해 달성 (κατάληψις: 확고하게 파악함)

> [English](./README.md)

## Katalepsis란?

스토아 철학의 κατάληψις (확고한 파악, 확실한 이해)를 현대적으로 재해석한 프로토콜 — 누가 만들었든 **맥락에 있는 대상을 사용자가 따라가며 검증된 이해에 도달**할 수 있게 합니다.

### 핵심 문제

대상이 복잡할 때 — 큰 변경, 남이 쓴 코드, 밀도 높은 논문 — 사용자는 종종 그것을 온전히 파악하지 못합니다 (`TargetUngrasped`). 이해했다고 생각하거나, 어디서부터 시작해야 할지 몰라 압도당할 수 있습니다.

### 해결책

**설명보다 이해 확인**: 일방적으로 설명하는 대신, AI가 사용자 자신의 답으로 이해를 확인합니다. 사용자가 무엇을 왜 이해하려는지 이미 말했다면 거기서 바로 확인을 시작하고, 아니라면 AI가 사용자의 말에 가까운 의도 기반 진입점을 먼저 보여 주며, 사용자는 그중 하나를 고르거나 자기 경로를 직접 말합니다. AI는 질문마다 대상의 실제 근거를 붙이고, 사용자의 답이 보인 것만 — 그리고 어떻게 보였는지(스스로, 사용자가 청한 단계 뒤에, 공개 뒤에)까지 — 기록합니다.

### 단순 설명과의 차이

| 차원 | 단순 설명 | Katalepsis |
|------|----------|------------|
| 방향 | AI가 말하고, 사용자가 듣는다 | AI가 묻고, 사용자가 보인다 |
| 진입점 | AI가 무엇을 설명할지 결정 | 사용자가 말한 목적, 또는 사용자가 고른 의도 기반 경로 |
| 확인 | 설명 후 가정됨 | 사용자 자신의 답으로 보이고, 대상에 비추어 확인됨 |
| 끝 | 정의되지 않음 | 사용자가 목적에 충분히 이해했다고 말함 — 아직 보이지 않은 것과 AI의 이견이 기록과 함께 보임 |

## 프로토콜 흐름

```
수집   → 대상의 근거와, 턴이 가리키는 출처를 지금 읽음
범위   → 사용자가 무엇을 무엇을 위해 이해하려는지 말함
         (자기 말로, 또는 범위가 열려 있는 동안 AI가 보인 진입점을 골라서)
확인   → 라운드마다 한 측면을 물음; 답이 그것을 보이거나, 놓치면 근거를 붙인
         공개나 판정이 이어짐 (gate interaction)
닫기   → 사용자가 충분히 이해했다고 말함; 기록은 보인 것과 그 방식, 아직
         보이지 않은 것, 이견을 보임
```

## 사용 시점

**사용**:
- 상당한 코드 변경이 들어온 뒤 — 누가 한 것이든
- 사용자가 "뭘 했어?", "설명해줘", "이해하고 싶어", "이게 이해가 안 돼", "못 따라가겠어"라고 할 때
- 복잡한 리팩토링, 새 기능, 아키텍처 변경

**건너뛰기**:
- 사소한 변경 (오타, 포매팅)
- 사용자가 이미 이해를 보여줌
- 사용자가 명시적으로 설명을 거부

## 사용법

```
/grasp
```

## 라운드가 살피는 것

| 측면 | 설명 |
|------|------|
| **일반 갭** | 사용자가 기대한 동작, 원인에 대한 이해, 영향 범위, 순서 파악이 대상이 실제로 하는 것과 다른 곳 — 먼저 사용자의 추론을 듣고, 그다음 그것을 가리는 근거를 인용해 판정 |
| **Horizon** | 사용자가 말하지 않았지만 목적에 필요한, 대상이 하는 일의 가장자리 — 대상의 근거에 기대야 하며, 먼저 일상 시나리오로만 묻고, 놓치면 근거와 함께 공개 |
| **Contradiction** | 같은 범위에서 함께 성립할 수 없는 출처 있는 두 진술 — 누구의 것인지에 따라 다룸: 사용자가 한쪽을 쥔 모순은 먼저 사용자의 설명을 청하고, 대상 안의 모순은 대상에 대한 발견으로 보이고, 앞선 AI 설명과의 모순은 AI 가 바로잡음 |
