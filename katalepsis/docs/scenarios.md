# Katalepsis 사용 시나리오

> 실사용 전제 — 이 시나리오들은 사용자가 해당 프로토콜을 의식적으로 호출(`/grasp`)하는 상황을 기술합니다.
> Skill이 세션에 로드되지 않으면 충돌이 발생하지 않습니다.

**프로토콜**: Katalepsis (`/grasp`)
**결핍 → 해소**: `TargetUngrasped → VerifiedUnderstanding`

---

### 1. AI가 작성한 재귀 SQL CTE 이해 `SW`

**사용자 맥락**: AI가 계층적 조직도 데이터를 쿼리하기 위해 재귀 CTE(Common Table Expression)를 작성했다. 쿼리는 정확히 동작하지만, 개발자가 재귀 종료 조건과 UNION ALL의 동작 방식을 이해하지 못한 상태다.

**트리거 발화**: "이 쿼리가 어떻게 동작하는지 설명해 달라" (사용자 주도 + 결과 R 존재)

**호출 예시**:
```
/grasp 이 재귀 CTE 쿼리가 어떻게 동작하는지, 특히 종료 조건과 UNION ALL 부분을 이해하고 싶어.
```

**결핍(전)**: 결과물 R(SQL 쿼리)이 이미 존재하고, 사용자가 이해 부족을 인지한 상태. 재귀 종료 조건과 UNION ALL 동작을 오해하면 수정 시 무한루프 위험.

**해결(후)**: 호출 발화가 이미 범위(종료 조건과 UNION ALL)와 목적을 말하므로 진입점 없이 바로 확인이 시작된다. SQL 근거를 연결한 소크라테스식 질문으로 반복 순서와 종료 조건을 사용자가 스스로 설명·예측하게 하고, 보인 측면과 그 방식, 아직 보이지 않은 측면을 기록한 채 사용자가 충분하다고 말할 때 VerifiedUnderstanding에 도달한다.

**인접 프로토콜 배제**: **Aitesis** — 실행 전 컨텍스트 부족이 아니라, 이미 완료된 결과물의 이해 검증이 목표다.

### 2. CQRS+이벤트 소싱 패턴 파악 `SW`

**사용자 맥락**: AI가 CQRS+이벤트 소싱 패턴으로 주문 처리 도메인을 구현했다. 코드는 동작하지만 개발자가 Command→Event→Projection 흐름과 eventual consistency 보장 방식을 확실히 이해하지 못한다.

**트리거 발화**: "이 아키텍처 패턴을 정확히 이해했는지 확인하고 싶다" (사용자 주도)

**호출 예시**:
```
/grasp CQRS+이벤트 소싱 패턴에서 Command→Event→Projection 흐름과 eventual consistency 보장 방식을 이해했는지 확인하고 싶어.
```

**결핍(전)**: 단일 코드가 아닌 아키텍처 패턴 전체의 이해가 부족. Command→Event→Projection 흐름의 오해로 잘못된 수정 위험.

**해결(후)**: Command/Event/Projection 근거를 연결한 질문에 사용자의 답이 보인 측면만 보인 것으로 기록된다 — 동의나 "알 것 같다"는 보인 것이 아니다. eventual consistency 가 깨지는 경우처럼 사용자가 말하지 않은 가장자리는 일상 시나리오로 먼저 묻고, 놓치면 근거와 함께 공개한 뒤 적용 질문으로 확인한다.

### 3. Git rebase 충돌 해결 결과 검증 `SW`

**사용자 맥락**: AI가 복잡한 rebase 충돌을 해결했는데, 15개 파일에 걸친 변경사항 중 어떤 것이 원래 브랜치의 변경이고 어떤 것이 충돌 해결을 위한 수정인지 개발자가 구분하지 못한다.

**트리거 발화**: "이 충돌 해결에서 무엇이 바뀌었는지 이해하고 싶다"

**호출 예시**:
```
/grasp rebase 충돌 해결에서 원래 브랜치 변경과 충돌 해결 수정을 구분해서 이해하고 싶어.
```

**결핍(전)**: AI 작업의 '차이'를 이해하는 것이 핵심. 원래 변경과 충돌 해결 수정을 구분하지 못하면 잘못된 롤백 위험.

**해결(후)**: 각 파일의 diff 근거로 변경 이유를 묻고, 사용자가 원래 변경과 충돌 해결 수정을 스스로 구분해 보인 파일과 아직 보이지 않은 파일이 기록에 남는다. 사용자가 롤백 판단을 앞두면 지금까지 보인 것과 남은 것, AI가 가진 반대 근거를 그 판단 앞에 보인다.

### 4. DCF 밸류에이션 모델 산출 결과 `KW`

**사용자 맥락**: AI가 3개년 DCF 밸류에이션 모델을 완성하여 기업가치 범위(3,200~4,100억 원)를 산출했다. 투자심사역이 결과의 논리적 근거를 이해하고 싶다.

**트리거 발화**: "이 숫자가 어떻게 나온 건지 설명해 줘" (수치 모델의 가정/계산 이해)

**호출 예시**:
```
/grasp DCF 밸류에이션 결과가 3,200~4,100억으로 나왔는데, 할인율 가정과 터미널 밸류 계산이 어떻게 이 범위를 만드는지 이해하고 싶어.
```

**결핍(전)**: 결과(R)가 이미 존재하고, 사용자는 할인율 가정, 터미널 밸류 계산, 감도 분석이 어떻게 결합되어 이 범위를 만들었는지를 이해하고 싶다.

**해결(후)**: 할인율, 터미널 밸류, 감도 분석을 산출 근거로 연결해 사용자가 범위가 어떻게 만들어지는지 예측·설명하게 한다. 사용자가 터미널 밸류만 보이고 충분하다고 닫으면, 감도 분석은 보이지 않은 측면으로 남고 AI의 이견이 있으면 함께 실린 채 VerifiedUnderstanding에 도달한다.

### 5. AI가 설계한 온라인 강의 가격 전략 3단계 티어 `CC`

**사용자 맥락**: AI가 시장 분석을 기반으로 3단계 가격 티어(기본/프로/엔터프라이즈)와 각 티어의 기능 구성을 제안했다. 강사가 티어 구성 논리를 이해하고 싶다.

**트리거 발화**: "프로 티어에 1:1 코칭을 넣고 기본에서 뺀 이유가 뭔지... walk me through 해 줘"

**호출 예시**:
```
/grasp 가격 티어 구성에서 프로 티어에 1:1 코칭을 넣고 기본에서 뺀 이유, 이 가격 차이가 전환율에 어떤 영향을 줄 것으로 본 건지 이해하고 싶어.
```

**결핍(전)**: 가격 전략의 논리를 소화하지 못한 상태. 비즈니스 전략의 논리 근거 이해가 필요하다.

**해결(후)**: 티어 구성의 전략 근거와 전환율 가정을 묻고, 사용자의 답이 AI의 앞선 설명과 어긋나면 누구의 모순인지에 따라 다룬다 — 사용자가 한쪽을 쥔 모순은 먼저 사용자의 설명을 듣는다. 사용자가 충분하다고 말할 때 보인 것, 보이지 않은 것, 이견을 실어 닫는다.

### 6. AI가 작성한 실행 계획 파일 이해 `PM`

**사용자 맥락**: AI가 릴리스 계획 Markdown을 작성했다. 목표, 단계, 리스크, 승인 조건이 길게 정리되어 있지만 사용자는 무엇을 먼저 승인해야 하고 어떤 가정이 깨지면 계획이 무효가 되는지 빠르게 파악해야 한다.

**트리거 발화**: "이 계획에서 내가 봐야 할 핵심만 먼저 잡아줘"

**호출 예시**:
```
/grasp 릴리스 계획에서 내가 승인해야 할 결정 포인트와 깨지면 위험한 가정을 이해하고 싶어.
```

**결핍(전)**: 결과물 R(계획 파일)이 존재하지만, 사용자의 의도는 "Plan/Scope/Risk 카테고리" 선택이 아니라 승인과 위험 파악이다.

**해결(후)**: 호출 발화가 범위를 말하면 그것으로 범위가 채워진다. 트리거 발화처럼 범위가 아직 열려 있으면 "승인 전에 봐야 할 결정 포인트", "깨지면 위험한 가정", "다음 실행 순서" 같은 진입점을 보이고 그 밖에는 묻지 않는다. 사용자가 고르거나 자기 말로 범위를 정하면, 계획의 섹션과 acceptance criteria에 근거시켜 확인한다.

### 7. AI가 정리한 Notion 의사결정 문서 이해 `DOC`

**사용자 맥락**: AI가 회의 내용을 Notion 문서처럼 정리했다. 합의, 보류, 담당자, 다음 액션이 섞여 있어 사용자는 문서의 어떤 부분이 확정된 약속이고 어떤 부분이 아직 질문인지 파악하지 못한다.

**트리거 발화**: "이 문서에서 확정된 것과 아직 아닌 걸 구분해 줘"

**호출 예시**:
```
/grasp 이 Notion 정리에서 확정된 결정, 담당자 약속, 아직 열린 질문을 이해하고 싶어.
```

**결핍(전)**: 결과물 R(문서)이 존재하고, 사용자는 섹션 카테고리보다 문서가 자신에게 요구하는 후속 행동을 이해해야 한다.

**해결(후)**: 범위가 열려 있으면 "확정된 약속", "내가 해야 할 후속 액션", "아직 열린 질문" 같은 진입점을 먼저 보이고, 사용자가 정한 범위를 문서의 항목별 근거에 연결해 사용자 자신의 답으로 이해를 확인한다. 문서 안에서 서로 어긋나는 두 항목은 대상에 대한 발견으로 보인다.
